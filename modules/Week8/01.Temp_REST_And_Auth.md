# REST and Authentication

## Overview

The exam prep chatbot needs to do one thing at its core: take a student's question, find the relevant lecture notes, and send both to an AI model that generates a clear answer.

That last step — sending data to an AI model — means your Python program has to talk to a server running somewhere else on the internet. To do that, you need to understand:

- What a client and server are
- What HTTP is and how communication happens
- What an API is and why it exists
- What REST is and why every AI API uses it
- How to prove your program has permission to use the API

Every concept in this file is introduced from scratch. By the end, you will have written a working API call for the exam prep chatbot.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Client** | The program making the request — your Python script |
| **Server** | The computer receiving the request and sending back a response |
| **HTTP** | The language computers use to communicate over the internet |
| **API** | A service that lets your program ask another program to do something |
| **REST** | A set of rules for how APIs should be structured |
| **Endpoint** | One specific URL that does one specific thing |
| **Request** | Your program asking the server for something |
| **Response** | The server's reply |
| **API key** | A secret string that identifies your account |
| **Environment variable** | A value stored in the operating system, not in your code |

## Client and Server — The Basic Idea

Before anything else, you need to understand the two sides of every internet communication.

**Think of it like ordering food by phone.** You are the client — you pick up the phone and make a request. The restaurant is the server — it receives your request, prepares the food, and sends it back. You do not need to know how the kitchen works. The restaurant does not need to know who you are beyond your order and address.

In software:
- The **client** is your Python program — it makes a request
- The **server** is a computer somewhere else — it receives the request, processes it, and sends back a response

For the exam prep chatbot:
- Your Python script is the client
- Anthropic's server is on the other side
- Your script sends the student's question
- Anthropic's server sends back the generated answer

```text
Your Python script          Anthropic's Server
(Client)                    (Server)

    │  "What is gradient      │
    │   descent?"             │
    │ ──────────────────────► │  processes the question
    │                         │
    │  "Gradient descent is   │
    │   an algorithm that..." │
    │ ◄────────────────────── │
```

Every time the chatbot answers a question, this exchange happens. Your script sends, the server processes, the server replies.

## HTTP — The Language of the Internet

The client and server need to speak the same language. That language is **HTTP** — HyperText Transfer Protocol.

HTTP is not something you install or import. It is the set of rules that defines how messages are formatted and sent over the internet. When you open a website in a browser, your browser is sending an HTTP request to a web server. When the page loads, that is the HTTP response.

Your Python program does exactly the same thing — except instead of a browser requesting a web page, it is your script requesting an AI-generated answer.

**Two things travel over HTTP:**

- **A request** — sent by the client. Says what it wants and includes any data needed
- **A response** — sent back by the server. Contains the result and a status code saying whether it worked

Everything in this file happens over HTTP.

## What is an API?

You now know that a client sends a request to a server over HTTP. But what exactly is the client asking for?

An **API** (Application Programming Interface) is a defined set of ways your program can interact with another service. It is the menu at a restaurant — it tells you what you can order, how to order it, and what you will get back.

**Why APIs exist:**

Anthropic has built a powerful AI model. They want developers to be able to use it — but they cannot give everyone direct access to their internal systems. Instead, they provide an API: a controlled, secure interface where your program can send a question and get an answer back, without ever touching the underlying model code.

**For the exam prep chatbot:**

Without the Anthropic API, you cannot use Claude at all. The API is the only way in.

```text
Your Python script
        │
        │  sends question + lecture notes
        ▼
Anthropic API  ←── the controlled interface
        │
        │  processes using Claude
        ▼
Returns generated answer
```

Every major AI service — OpenAI, Google, Hugging Face — exposes an API. The concepts you learn here apply to all of them.

## What is REST?

Now that you know what an API is, here is why REST matters.

Different developers build APIs in different ways. Without agreed rules, every API would work differently — different URL formats, different ways to send data, different response structures. You would have to learn a completely new system for every API you use.

**REST** (Representational State Transfer) is a set of agreed rules that makes APIs consistent. When an API follows REST rules, you already know roughly how it works — even if you have never used it before.

Think of it like traffic rules. Different countries drive on different sides of the road — but within one country, everyone follows the same rules. REST is the traffic rules for APIs. Follow them, and any client can talk to any REST API.

**The key REST rules:**
- Every resource (a message, a model, a document) has a URL
- You use standard HTTP methods to say what you want to do
- Data is sent and received as JSON
- Every request is independent — the server does not remember previous requests

The Anthropic API, OpenAI API, and Google AI API are all REST APIs. Learn REST once, and you can work with all of them.

## URLs, Base URLs, and Endpoints

Every resource in a REST API has an address — a URL. Let us break down what a URL looks like for the exam prep chatbot.

**A URL has parts:**

```text
https://api.anthropic.com/v1/messages

https://          ← the protocol — always https for secure APIs
api.anthropic.com ← the base URL — the root address of the API
/v1/messages      ← the endpoint — the specific operation
```

**Base URL** — the root address of the API. Every request to Anthropic starts here:
```text
https://api.anthropic.com
```

**Endpoint** — one specific path that does one specific thing:
```text
/v1/messages      → send a message, get a response back
/v1/models        → get a list of available models
```

**Full URL** — base URL + endpoint:
```text
https://api.anthropic.com/v1/messages
```

Different endpoints do different things — even on the same server:

| Full URL | What it does |
|---|---|
| `https://api.anthropic.com/v1/messages` | Send a message to Claude, get a response |
| `https://api.openai.com/v1/embeddings` | Convert text to an embedding vector |
| `https://api.openai.com/v1/models` | List all available models |

For the exam prep chatbot, the only endpoint needed is `https://api.anthropic.com/v1/messages` — send the student's question with lecture notes, receive the generated answer.

---

## HTTP Methods — What Action Are You Taking?

When you send an HTTP request, you need to say what kind of action you want to perform. HTTP defines four main methods for this:

| Method | What it means | Everyday example |
|---|---|---|
| **GET** | Fetch something — read only, send no data | Checking your email inbox |
| **POST** | Send data to create or trigger something | Sending a new email |
| **PUT** | Send data to update something that exists | Editing a sent email (in a draft) |
| **DELETE** | Remove something | Deleting an email |

**For the exam prep chatbot:**

Sending a question to Claude is a **POST** request. You are creating a new message and triggering a response. You are sending data — the question and lecture notes — to the server.

Almost all AI inference calls are POST:
- Sending a question → POST
- Generating an embedding → POST
- Asking for a completion → POST

GET is used for reading existing data — like listing available models — where you are not sending any new data to process.

## JSON — The Format Data Travels In

When your program sends data to the API, it sends it as **JSON** — JavaScript Object Notation. When the API responds, it also sends JSON back.

You already know JSON from the File Handling series. Here is a quick reminder of what it looks like:

```json
{
  "question": "What is gradient descent?",
  "context": "Gradient descent minimises the loss function...",
  "model": "claude-sonnet-4-6"
}
```

JSON is just a text format for structured data — keys and values, like a Python dictionary. Every AI API uses JSON for both sending and receiving data.

**From JSON to Python dictionary:**

When the API sends a JSON response, `response.json()` converts it to a Python dictionary you can work with normally:

```python
data = response.json()
print(data["content"][0]["text"])   # the generated answer
```

## Anatomy of an HTTP Request

Every HTTP request has three parts. Understanding all three makes debugging API calls straightforward.

**Think of it like sending a parcel:**
- The **URL** is the delivery address — where the parcel is going
- The **headers** are the label on the parcel — metadata about what is inside and who sent it
- The **body** is the actual contents inside the parcel

Here is the complete request the exam prep chatbot sends when a student asks *"What is gradient descent?"*:

```text
POST https://api.anthropic.com/v1/messages
│
├── HEADERS
│   ├── Content-Type: application/json    ← tells the server the body is JSON
│   ├── x-api-key: sk-ant-...            ← proves this program has permission
│   └── anthropic-version: 2023-06-01    ← which version of the API to use
│
└── BODY (JSON)
    {
      "model": "claude-sonnet-4-6",
      "max_tokens": 1024,
      "system": "You are an exam prep assistant. Answer using lecture notes only.",
      "messages": [
        {
          "role": "user",
          "content": "Lecture notes: Gradient descent minimises the loss function...\n\nQuestion: What is gradient descent?"
        }
      ]
    }
```

**The URL** — `POST https://api.anthropic.com/v1/messages` — says: use POST method, send to this address.

**The headers** — three pieces of metadata:
- `Content-Type: application/json` — the body is JSON formatted text
- `x-api-key` — the API key that identifies this account (covered in detail shortly)
- `anthropic-version` — Anthropic requires this to know which version of the API to use

**The body** — the actual data being sent. For the exam prep chatbot:
- `model` — which AI model to use
- `max_tokens` — maximum length of the response
- `system` — instructions telling Claude how to behave
- `messages` — the student's question, with the lecture notes included as context

## Anatomy of an HTTP Response

The server processes the request and sends back a response. Every response has three parts — exactly mirroring the request structure:

```text
HTTP/1.1 200 OK
│
├── STATUS CODE: 200
│
├── HEADERS
│   ├── Content-Type: application/json
│   ├── x-ratelimit-requests-remaining: 47
│   └── request-id: req_abc123
│
└── BODY (JSON)
    {
      "id": "msg_abc123",
      "type": "message",
      "role": "assistant",
      "content": [
        {
          "type": "text",
          "text": "Gradient descent is an optimisation algorithm that adjusts a model's parameters step by step to minimise the error in its predictions."
        }
      ],
      "model": "claude-sonnet-4-6",
      "usage": {
        "input_tokens": 87,
        "output_tokens": 32
      }
    }
```

**The status code** — the first thing to check. It tells you immediately whether the request worked:

| Code | Meaning | What it means for the chatbot |
|---|---|---|
| `200` | Success | The answer is in the body — use it |
| `400` | Bad request | Something wrong in what was sent — fix the code |
| `401` | Unauthorised | API key is missing or wrong — check the key |
| `429` | Too many requests | Rate limit hit — wait and retry |
| `500` | Server error | Problem on Anthropic's side — try again |

The next file covers how to handle each of these correctly.

**The response headers** — useful metadata from the server:
- `x-ratelimit-requests-remaining: 47` — how many more requests are allowed before hitting the rate limit. The next file covers what to do when this hits zero

**The response body** — the JSON data sent back. For the chatbot:

| Field | What it is | Do you need it? |
|---|---|---|
| `content[0]["text"]` | The generated answer | **Yes — always** |
| `usage.input_tokens` | How many tokens the question used | Yes — for cost tracking |
| `usage.output_tokens` | How many tokens the answer used | Yes — for cost tracking |
| `id` | Unique ID for this request | Only for debugging |
| `type` | Always `"message"` | No |
| `role` | Always `"assistant"` | No |

The one line you will use in almost every chatbot response:
```python
answer = response.json()["content"][0]["text"]
```

## Making the Request in Python

Now that every concept is clear, here is the actual Python code that sends the request:

```python
import requests

response = requests.post(
    "https://api.anthropic.com/v1/messages",
    headers={
        "Content-Type": "application/json",
        "x-api-key": "sk-ant-YOUR-KEY-HERE",    # ← NEVER do this in real code
        "anthropic-version": "2023-06-01"
    },
    json={
        "model": "claude-sonnet-4-6",
        "max_tokens": 1024,
        "system": "You are an exam prep assistant. Answer using the lecture notes provided.",
        "messages": [
            {
                "role": "user",
                "content": "Lecture notes: Gradient descent minimises the loss function by adjusting parameters iteratively.\n\nQuestion: What is gradient descent?"
            }
        ]
    }
)

print(response.status_code)
print(response.json()["content"][0]["text"])
```

**Output**

```text
200
Gradient descent is an optimisation algorithm that adjusts a model's parameters
step by step to minimise the error in its predictions.
```

This works — but notice line 6. The API key is written directly in the code. This is called **hardcoding** and it is dangerous. The next section explains why, and how to fix it.

## Authentication — Why the Server Needs to Know Who You Are

The Anthropic API is not free or open to everyone. Every request costs tokens — and those tokens cost money. Anthropic needs to know:
- Who is making this request
- Are they allowed to use this API
- Which account to bill for the tokens used

This is where **authentication** comes in. Authentication means proving your identity to the server.

### What an API Key Is

An API key is a long, unique secret string — something like:
```text
sk-ant-api03-abc123xyz789...
```

It is tied to your Anthropic account. When you include it in a request, the server knows exactly who is making the call. If the key is missing or wrong, the server returns `401 Unauthorised` and refuses to process the request.

### The Bearer Token Pattern

The standard way to send an API key is in the `Authorization` header as a **Bearer token**:

```text
Authorization: Bearer sk-ant-YOUR-KEY-HERE
```

"Bearer" simply means "the program carrying this token is allowed in" — like showing a wristband at an event entrance. The wristband does not explain who you are. It just proves you have permission.

Anthropic uses a slightly different header name — `x-api-key` — but the concept is identical. OpenAI uses `Authorization: Bearer`. Always check the specific API's documentation for which format it expects.

### Why You Must Never Hardcode an API Key

```python
# THIS IS DANGEROUS — never write this
api_key = "sk-ant-api03-abc123..."
```

When this code is committed to a Git repository — even a private one — the key is stored in the version history permanently. If the repository is ever made public, or if someone gains access to it, the key is visible.

GitHub automatically scans public repositories for exposed API keys. Within minutes of a key being pushed publicly, automated bots find it and start using it. You get billed for every request they make.

This happens to students constantly. A project is finished, the repository is made public for a portfolio, and within hours the API quota is exhausted from someone else's usage.

## Safe Key Handling

### Step 1 — Store the Key as an Environment Variable

An environment variable is a value stored in the operating system — not in your code. Your program reads it at runtime, so the key never appears in any file.

**Setting it in the terminal:**

On Mac/Linux:
```bash
export ANTHROPIC_API_KEY="sk-ant-YOUR-KEY-HERE"
```

On Windows:
```bash
set ANTHROPIC_API_KEY=sk-ant-YOUR-KEY-HERE
```

**Reading it in Python:**

```python
import os

api_key = os.environ.get("ANTHROPIC_API_KEY")
print(api_key)   # prints the key — but the key itself is not in the code
```

The key is on the machine but not in the file. If someone reads the code, they see `os.environ.get("ANTHROPIC_API_KEY")` — not the actual key.

### Step 2 — Use a .env File for Convenience

Setting environment variables in the terminal resets every time the terminal is closed. A `.env` file stores them permanently on the machine.

**Install python-dotenv:**

```bash
pip install python-dotenv
```

**Create a file called `.env` in your project folder:**

```text
ANTHROPIC_API_KEY=sk-ant-YOUR-KEY-HERE
```

No quotes. No spaces around `=`. One variable per line.

**Load it at the start of your Python script:**

```python
from dotenv import load_dotenv
import os

load_dotenv()   # reads .env and loads every variable into the environment

api_key = os.environ.get("ANTHROPIC_API_KEY")
```

`load_dotenv()` must be called before `os.environ.get()`. Without it, the `.env` file is not read and the key returns `None`.

### Step 3 — Keep .env Out of Git with .gitignore

A `.gitignore` file tells Git which files to never track. The `.env` file must always be listed here.

**Create a file called `.gitignore` in your project folder:**

```text
.env
__pycache__/
*.pyc
```

**The order matters — always do this first:**
1. Create `.gitignore`
2. Then create `.env`

If `.env` is added to Git even once before `.gitignore` is set up, it is in the history permanently. Deleting the file and committing again does not remove it from history. The only fix is to revoke the key immediately and generate a new one.

**Verify `.env` is being ignored:**

```bash
git status
```

If `.env` does not appear — it is correctly ignored. If it does appear — stop, add it to `.gitignore`, and do not commit.

### What to Do If a Key Is Exposed

If a key is accidentally committed to a public repository:

1. Go to the Anthropic Console immediately
2. Revoke the key — this deactivates it within seconds
3. Generate a new key
4. Update `.env` with the new key
5. Check the usage dashboard for unexpected charges

Do not just delete the commit or make the repository private. The key is in Git history and still visible to anyone who cloned it before you acted.

## The Complete Safe API Call

Here is the full `ask_chatbot()` function — combining everything from this file into one safe, working implementation:

```python
from dotenv import load_dotenv
import os
import requests

load_dotenv()   # loads ANTHROPIC_API_KEY from .env into the environment

def ask_chatbot(question: str, context: str) -> str:
    # question: str  means this parameter expects a string
    # context: str   means this parameter expects a string
    # -> str         means this function returns a string
    # these are optional type hints — Python does not enforce them, they are for readability
    """
    Send a student's exam question to the Anthropic API.
    context: the relevant lecture notes retrieved from ChromaDB.
    Returns the generated answer as a string.
    """
    api_key = os.environ.get("ANTHROPIC_API_KEY")
    if not api_key:
        raise ValueError("ANTHROPIC_API_KEY not set — check your .env file")
        # stops immediately with a clear message instead of a confusing error later

    response = requests.post(
        "https://api.anthropic.com/v1/messages",
        headers={
            "Content-Type": "application/json",  # body is JSON
            "x-api-key": api_key,                # key from environment — never hardcoded
            "anthropic-version": "2023-06-01"    # required by Anthropic
        },
        json={
            "model": "claude-sonnet-4-6",
            "max_tokens": 1024,
            "system": (
                "You are an exam preparation assistant for a BTech AI programme. "
                "Answer the student's question using only the lecture notes provided. "
                "If the answer is not in the notes, say so clearly rather than guessing."
            ),
            "messages": [
                {
                    "role": "user",
                    "content": f"Lecture notes:\n{context}\n\nQuestion: {question}"
                    # f-string inserts the values of context and question into the message
                    # \n means new line — separates the notes from the question visually
                }
            ]
        }
    )

    response.raise_for_status()
    # if status code is 4xx or 5xx, this raises an exception immediately
    # prevents the next line from trying to read an error message as if it were an answer
    # the next file covers how to handle specific error codes

    return response.json()["content"][0]["text"]
    # content is a list — [0] gets the first item
    # ["text"] gets the generated answer string


# Test the function
question = "What is gradient descent?"
context = (
    "Gradient descent is an optimisation algorithm used to train machine learning models. "
    "It works by calculating the gradient of the loss function with respect to each parameter, "
    "then adjusting the parameters in the direction that reduces the loss. "
    "This process repeats until the loss is minimised or a stopping condition is met."
)

answer = ask_chatbot(question, context)
print(answer)
```

**Output**

```text
Gradient descent is an optimisation algorithm that trains machine learning models by
repeatedly adjusting their parameters in the direction that reduces the loss function.
It calculates the gradient — the direction of steepest increase — and moves in the
opposite direction, step by step, until the loss is minimised.
```

The context here is hardcoded for testing. In the real chatbot, this context comes from ChromaDB — the vector index finds which lecture notes are most relevant to the student's question and passes them to this function automatically. That is covered in the Embeddings and ChromaDB files.

## Common Mistakes

- **Hardcoding the API key** — if the file is shared or committed to Git, the key is exposed permanently. Always use `os.environ.get()`.
- **Forgetting `load_dotenv()`** — the `.env` file is not loaded automatically. Without this call, `os.environ.get()` returns `None` and the request fails with a confusing error.
- **Creating `.env` before `.gitignore`** — if `.env` is committed even once, it is in Git history forever. Add `.gitignore` first.
- **Not checking for `None` after `os.environ.get()`** — a missing key produces a cryptic error inside the request. The `if not api_key` check gives a clear message instead.
- **Forgetting `Content-Type: application/json`** — the server cannot parse the body and returns a 400 error.
- **Forgetting `anthropic-version` header** — Anthropic requires this. Missing it returns a 400.
- **Using `response.json()` without `raise_for_status()` first** — if the request failed, the body is an error message not an answer. `raise_for_status()` ensures failures are caught before parsing.
