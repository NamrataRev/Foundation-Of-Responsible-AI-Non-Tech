# Vector Index — FAISS and ChromaDB

## The Problem This Solves

File 3 produced embeddings for all the exam prep documents — lecture notes, past papers, and model answers. Each document is now a list of 384 numbers representing its meaning.

But embeddings sitting in a Python list are not searchable. When a student asks a question, the chatbot needs to compare the question's embedding against every stored document embedding and return the most similar ones. With 10 documents this works fine. With 500 documents across a full semester's worth of notes, doing this comparison one by one becomes slow. With 10,000 documents, it becomes impractical.

A **vector index** solves this. It organises embeddings so that similar ones can be found quickly — without checking every single document. It is the difference between searching an unsorted pile of books and using a library catalogue.

This file covers two tools that do this:
- **FAISS** — fast, lightweight, good for learning and speed
- **ChromaDB** — a full vector database with persistent storage and metadata filtering, suited to the exam prep chatbot

By the end, the chatbot will retrieve the right lecture notes for any student question and pass them to `ask_chatbot()` — completing the full pipeline.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Vector index** | A data structure that organises embeddings for fast similarity search |
| **Brute-force search** | Comparing a query against every stored vector one by one — slow at scale |
| **k** | The number of top results to return — "find the k most similar documents" |
| **Collection** | ChromaDB's name for a named group of stored documents and their embeddings |
| **Persistent storage** | Data saved to disk — survives when the program stops and starts again |
| **Metadata** | Extra information stored alongside the embedding — type, subject, topic |
| **Filtering** | Searching only within a subset of documents using metadata conditions |
| **RAG** | Retrieval-Augmented Generation — finding relevant documents, then using them as context for an LLM |

## Why Not Just Search the List?

Before introducing FAISS and ChromaDB, it is worth understanding exactly what problem they solve.

If all document embeddings are stored in a Python list, finding the most similar one to a query means calculating cosine similarity between the query and every single document:

```python
# brute-force — works but slow at scale
similarities = []
for i, doc_embedding in enumerate(all_embeddings):
    score = cosine_similarity(query_embedding, doc_embedding)
    similarities.append((score, i))

similarities.sort(reverse=True)
top_3 = similarities[:3]
```

With 10 documents this takes milliseconds. With 10,000 documents it takes seconds. With 1 million documents it takes minutes — per query.

A vector index pre-organises the embeddings so the most similar ones are found in a fraction of the time, without checking every document. Think of it like the index at the back of a textbook — you do not read every page to find "gradient descent." You look it up in the index, which points directly to the right page.

## FAISS — Fast Similarity Search

FAISS (Facebook AI Similarity Search) is a library built specifically for finding similar vectors quickly. It is the most widely used vector search library in research and production.

### Installing FAISS

```bash
pip install faiss-cpu
```

`faiss-cpu` runs on any machine. `faiss-gpu` exists for GPU-accelerated search on very large datasets — not needed for the exam prep chatbot.

### Creating an Index and Adding Vectors

```python
import faiss
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("all-MiniLM-L6-v2")

documents = [
    "Gradient descent minimises the loss function by adjusting parameters iteratively.",
    "Backpropagation computes gradients layer by layer using the chain rule.",
    "The learning rate controls how large each parameter update step is.",
    "Overfitting occurs when a model learns the training data too well and fails on new data.",
    "A confusion matrix shows the counts of true positives, false positives, true negatives, and false negatives."
]

embeddings = model.encode(documents)
embeddings = np.array(embeddings, dtype="float32")
# FAISS requires float32 — numpy array, not a Python list

dimension = embeddings.shape[1]   # 384 for all-MiniLM-L6-v2
print(f"Embedding dimension: {dimension}")

index = faiss.IndexFlatL2(dimension)
# IndexFlatL2 = exact search using L2 (Euclidean) distance
# the simplest index type — good for learning and small datasets

index.add(embeddings)
print(f"Documents in index: {index.ntotal}")
```

**Output**

```text
Embedding dimension: 384
Documents in index: 5
```

`faiss.IndexFlatL2(dimension)` creates a new empty index. The number you pass in must match the dimension of the embeddings you will add — 384 for `all-MiniLM-L6-v2`. If you add a vector with a different dimension, FAISS raises an error.

`index.add(embeddings)` adds all five document vectors at once. FAISS assigns each one an integer ID automatically — 0 for the first, 1 for the second, and so on.

### Searching the Index

```python
query = "how does the algorithm adjust when it gets something wrong?"
query_embedding = model.encode([query])
query_embedding = np.array(query_embedding, dtype="float32")

k = 3   # return the 3 most similar documents

distances, indices = index.search(query_embedding, k)
# distances: how far each result is from the query (lower = more similar)
# indices: the position of each result in the original documents list

print("Top matches:")
for i, idx in enumerate(indices[0]):
    print(f"  {i+1}. [{distances[0][i]:.3f}] {documents[idx]}")
```

**Output**

```text
Top matches:
  1. [0.312] Gradient descent minimises the loss function by adjusting parameters iteratively.
  2. [0.441] Backpropagation computes gradients layer by layer using the chain rule.
  3. [0.589] The learning rate controls how large each parameter update step is.
```

`distances` are L2 distances — lower means more similar. `indices` are the integer IDs FAISS assigned when the documents were added. Use those IDs to look up the original document text from the `documents` list.

### Saving and Loading a FAISS Index

FAISS indexes live in memory — they are lost when the program stops. Save them to disk so you do not have to re-embed all documents every time:

```python
faiss.write_index(index, "exam_prep.index")
print("Index saved")

loaded_index = faiss.read_index("exam_prep.index")
print(f"Loaded index with {loaded_index.ntotal} documents")
```

**Output**

```text
Index saved
Loaded index with 5 documents
```

### FAISS Limitation — No Text Storage

FAISS stores only vectors and integer IDs. It has no built-in way to store the original text, metadata, or any other information alongside the vectors. You have to maintain a separate mapping yourself:

```python
# you must manage this mapping manually
id_to_document = {i: doc for i, doc in enumerate(documents)}

distances, indices = index.search(query_embedding, 3)
for idx in indices[0]:
    print(id_to_document[idx])
```

This works for small projects. For anything more complex — multiple document types, filtering by subject, storing metadata — ChromaDB handles all of this automatically.

## ChromaDB — A Purpose-Built Vector Database

ChromaDB is a vector database designed specifically for AI applications. It stores the vector, the original text, and any metadata together — and lets you filter searches by metadata before comparing vectors.

For the exam prep chatbot, this means: "find the 3 most similar documents to this query, but only look in machine learning notes, not past papers."

### Installing ChromaDB

```bash
pip install chromadb
```

### Creating a Client and Collection

```python
import chromadb

client = chromadb.Client()
# in-memory client — data is lost when the program stops
# use PersistentClient (shown later) to save to disk

collection = client.create_collection("exam_prep")
# a collection is a named group of documents
# think of it like a table in a database
print(f"Collection created: {collection.name}")
```

**Output**

```text
Collection created: exam_prep
```

### Adding Documents

ChromaDB can embed documents automatically if you provide an embedding function — or you can provide your own pre-computed embeddings. The cleanest approach for the exam prep chatbot is to provide both the text and the embeddings together, along with metadata and IDs:

```python
from sentence_transformers import SentenceTransformer
import chromadb

model = SentenceTransformer("all-MiniLM-L6-v2")

documents = [
    {
        "id": "ln_001",
        "text": "Gradient descent minimises the loss function by adjusting parameters iteratively.",
        "type": "lecture_note",
        "subject": "machine_learning",
        "topic": "gradient_descent"
    },
    {
        "id": "ln_002",
        "text": "Backpropagation computes gradients layer by layer using the chain rule.",
        "type": "lecture_note",
        "subject": "machine_learning",
        "topic": "backpropagation"
    },
    {
        "id": "pp_001",
        "text": "Q4b (2024): Describe the role of the learning rate in gradient descent.",
        "type": "past_paper",
        "subject": "machine_learning",
        "topic": "gradient_descent"
    },
    {
        "id": "ma_001",
        "text": "A4b: A high learning rate causes overshooting. A low learning rate causes slow convergence.",
        "type": "model_answer",
        "subject": "machine_learning",
        "topic": "gradient_descent"
    },
    {
        "id": "ln_003",
        "text": "Overfitting occurs when a model memorises training data and fails to generalise.",
        "type": "lecture_note",
        "subject": "machine_learning",
        "topic": "overfitting"
    }
]

texts      = [doc["text"] for doc in documents]
ids        = [doc["id"]   for doc in documents]
metadatas  = [{"type": doc["type"], "subject": doc["subject"], "topic": doc["topic"]}
              for doc in documents]
embeddings = model.encode(texts).tolist()
# .tolist() converts numpy array to a plain Python list — ChromaDB requires this

client = chromadb.Client()
collection = client.create_collection("exam_prep")

collection.add(
    ids=ids,
    documents=texts,
    embeddings=embeddings,
    metadatas=metadatas
)

print(f"Documents stored: {collection.count()}")
```

**Output**

```text
Documents stored: 5
```

ChromaDB stores the text, embedding, metadata, and ID together. No manual mapping needed.

### Querying the Collection

```python
query = "how does the algorithm adjust when it gets something wrong?"
query_embedding = model.encode([query]).tolist()

results = collection.query(
    query_embeddings=query_embedding,
    n_results=3
    # n_results = how many top matches to return (equivalent to k in FAISS)
)

print("Top matches:")
for i, doc in enumerate(results["documents"][0]):
    distance = results["distances"][0][i]
    metadata = results["metadatas"][0][i]
    print(f"\n  {i+1}. [{distance:.3f}] ({metadata['type']}) {doc}")
```

**Output**

```text
Top matches:

  1. [0.312] (lecture_note) Gradient descent minimises the loss function by adjusting parameters iteratively.
  2. [0.441] (lecture_note) Backpropagation computes gradients layer by layer using the chain rule.
  3. [0.521] (past_paper) Q4b (2024): Describe the role of the learning rate in gradient descent.
```

The results include the document text, similarity distance, and metadata — all in one response.

### Filtering by Metadata

The student is specifically revising for the machine learning exam and only wants lecture notes — not past papers. ChromaDB's `where=` clause filters before searching:

```python
results = collection.query(
    query_embeddings=query_embedding,
    n_results=3,
    where={"type": "lecture_note"}
    # only search within lecture notes — ignore past papers and model answers
)

print("Lecture notes only:")
for doc in results["documents"][0]:
    print(f"  - {doc}")
```

**Output**

```text
Lecture notes only:
  - Gradient descent minimises the loss function by adjusting parameters iteratively.
  - Backpropagation computes gradients layer by layer using the chain rule.
  - Overfitting occurs when a model memorises training data and fails to generalise.
```

The past paper and model answer are excluded even though they were semantically relevant. The `where=` clause filters by metadata before the similarity comparison runs.

Other useful filter examples for the exam prep chatbot:

```python
where={"topic": "gradient_descent"}         # only gradient descent documents
where={"type": "past_paper"}                # only past exam questions
where={"subject": "machine_learning"}       # only ML subject documents
```

### Persistent Storage — Saving to Disk

The in-memory client loses all data when the program stops. Use `PersistentClient` to save to disk:

```python
import chromadb

client = chromadb.PersistentClient(path="./exam_prep_db")
# creates a folder called exam_prep_db in the current directory
# all collections and documents are saved there automatically

collection = client.get_or_create_collection("exam_prep")
# get_or_create_collection: returns existing collection if it exists,
# creates a new one if it does not — safe to call on every startup
```

Now the documents survive between program runs. Embed once, store once, search as many times as needed.

### Updating and Deleting Documents

When lecture notes are updated at the start of a new semester:

```python
# update an existing document
collection.update(
    ids=["ln_001"],
    documents=["Gradient descent minimises the loss by computing gradients and taking small steps."],
    embeddings=model.encode(["Gradient descent minimises the loss by computing gradients and taking small steps."]).tolist(),
    metadatas=[{"type": "lecture_note", "subject": "machine_learning", "topic": "gradient_descent"}]
)

# delete a document that is no longer relevant
collection.delete(ids=["pp_001"])

print(f"Documents after update: {collection.count()}")
```

**Output**

```text
Documents after update: 4
```

## The Complete RAG Pipeline

All four files now connect into one working system. A student types a question. The chatbot retrieves the relevant course material. The LLM generates a grounded answer.

```python
from sentence_transformers import SentenceTransformer
from dotenv import load_dotenv
import chromadb
import os
import time
import random
import requests

load_dotenv()

# ── Setup ──────────────────────────────────────────────────────────────
embed_model = SentenceTransformer("all-MiniLM-L6-v2")

client     = chromadb.PersistentClient(path="./exam_prep_db")
collection = client.get_or_create_collection("exam_prep")

# ── Step 1: Index documents (run once — skip if already stored) ────────
if collection.count() == 0:
    documents = [
        {"id": "ln_001", "text": "Gradient descent minimises the loss function by adjusting parameters iteratively.", "type": "lecture_note", "subject": "machine_learning", "topic": "gradient_descent"},
        {"id": "ln_002", "text": "Backpropagation computes gradients layer by layer using the chain rule.",           "type": "lecture_note", "subject": "machine_learning", "topic": "backpropagation"},
        {"id": "ln_003", "text": "Overfitting occurs when a model memorises training data and fails to generalise.", "type": "lecture_note", "subject": "machine_learning", "topic": "overfitting"},
        {"id": "pp_001", "text": "Q4b (2024): Describe the role of the learning rate in gradient descent.",          "type": "past_paper",   "subject": "machine_learning", "topic": "gradient_descent"},
        {"id": "ma_001", "text": "A4b: A high learning rate causes overshooting. A low rate causes slow convergence.","type": "model_answer", "subject": "machine_learning", "topic": "gradient_descent"},
    ]
    texts     = [d["text"] for d in documents]
    ids       = [d["id"]   for d in documents]
    metas     = [{"type": d["type"], "subject": d["subject"], "topic": d["topic"]} for d in documents]
    embs      = embed_model.encode(texts).tolist()
    collection.add(ids=ids, documents=texts, embeddings=embs, metadatas=metas)
    print(f"Indexed {collection.count()} documents")

# ── Step 2: Retrieve relevant documents (File 3 + File 4) ─────────────
def retrieve(question: str, n: int = 3, doc_type: str = None) -> str:
    query_emb = embed_model.encode([question]).tolist()
    where     = {"type": doc_type} if doc_type else None
    results   = collection.query(query_embeddings=query_emb,
                                 n_results=n, where=where)
    return "\n\n".join(results["documents"][0])
    # joins the top n matching documents into one context string

# ── Step 3: Retry wrapper (File 2) ─────────────────────────────────────
def call_api_with_retry(payload: dict, max_retries: int = 4) -> dict:
    api_key = os.environ.get("ANTHROPIC_API_KEY")
    url     = "https://api.anthropic.com/v1/messages"
    headers = {"Content-Type": "application/json",
               "x-api-key": api_key,
               "anthropic-version": "2023-06-01"}
    for attempt in range(max_retries):
        response = requests.post(url, headers=headers,
                                 json=payload, timeout=10)
        if response.status_code == 200:
            return response.json()
        if response.status_code == 429 or response.status_code >= 500:
            wait = (2 ** attempt) + random.uniform(0, 1)
            print(f"Attempt {attempt+1} failed ({response.status_code}). Retrying in {wait:.1f}s...")
            time.sleep(wait)
            continue
        response.raise_for_status()
    raise RuntimeError(f"API call failed after {max_retries} attempts")

# ── Step 4: Generate answer (File 1) ───────────────────────────────────
def ask_chatbot(question: str, context: str) -> str:
    payload = {
        "model": "claude-sonnet-4-6",
        "max_tokens": 1024,
        "system": (
            "You are an exam preparation assistant for a BTech AI programme. "
            "Answer the student's question using only the lecture notes provided. "
            "If the answer is not in the notes, say so clearly rather than guessing."
        ),
        "messages": [
            {"role": "user",
             "content": f"Lecture notes:\n{context}\n\nQuestion: {question}"}
        ]
    }
    result = call_api_with_retry(payload)
    return result["content"][0]["text"]

# ── Full pipeline ───────────────────────────────────────────────────────
question = "how does the algorithm adjust when it gets something wrong?"

context  = retrieve(question, n=3, doc_type="lecture_note")
# retrieves the 3 most relevant lecture notes for this question
# filters to lecture_note type only — excludes past papers and model answers

answer   = ask_chatbot(question, context)
print(answer)
```

**Output**

```text
Indexed 5 documents
The algorithm adjusts by computing the gradient of the loss function — a measure 
of how wrong the prediction was — and then updating its parameters in the direction 
that reduces that error. This process, called gradient descent, repeats iteratively 
until the loss is minimised. The size of each adjustment is controlled by the 
learning rate.
```

The answer is grounded in the lecture notes. The student gets a clear, course-specific explanation — not a generic internet answer.

## FAISS vs ChromaDB — When to Use Which

| | FAISS | ChromaDB |
|---|---|---|
| Storage | In memory (needs manual save/load) | Persistent by default |
| Text storage | No — vectors and IDs only | Yes — text, metadata, embeddings together |
| Metadata filtering | No | Yes — `where=` clause |
| Best for | Learning, benchmarking, full control over storage | Practical RAG projects, persistence, filtering |
| Setup complexity | Lower | Slightly higher |

For the exam prep chatbot — use **ChromaDB**. Persistence means documents are embedded once and available on every startup. Metadata filtering means lecture notes, past papers, and model answers can be searched separately.

For a quick experiment or a research benchmark — use **FAISS**. Fewer concepts, faster to set up, and the search algorithm is the same.

## Common Mistakes

- **Forgetting `.tolist()` when passing embeddings to ChromaDB** — ChromaDB requires plain Python lists, not numpy arrays. Always call `.tolist()` on the output of `model.encode()`.
- **Re-indexing documents on every startup** — embedding is slow and unnecessary if documents have not changed. Check `collection.count()` first and only index if the collection is empty.
- **Using `create_collection()` instead of `get_or_create_collection()`** — `create_collection()` raises an error if the collection already exists. `get_or_create_collection()` is safe to call every time.
- **Passing the wrong dimension to `faiss.IndexFlatL2()`** — the number must match the embedding model's output dimension exactly. `all-MiniLM-L6-v2` is 384. Passing 512 causes a silent mismatch.
- **Not saving the FAISS index to disk** — FAISS is in-memory only. Forgetting `faiss.write_index()` means re-embedding all documents next time the program runs.
- **Filtering with `where=` when the metadata key does not exist** — if some documents were added without a `type` field, `where={"type": "lecture_note"}` will return zero results for those documents. Always add consistent metadata when indexing.
- **Retrieving too many results** — passing `n_results=20` when the LLM context window is limited causes the context to overflow. Start with 3 to 5 results and adjust based on the average document length.
