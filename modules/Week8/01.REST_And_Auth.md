# REST and Authentication

## The Problem This Solves

The exam prep chatbot has one job: take a student's question, combine it with the relevant lecture notes, and send both to an AI model that generates a clear answer.

That last step — sending data to an AI model running on Anthropic's servers — requires two things to work correctly:

**Structuring the request so the server understands it.** Anthropic's API expects a specific format — the right URL, the right headers, the right JSON body. Send anything incorrectly and the server rejects it. This is what **REST** defines — a set of rules that every AI API follows for how requests and responses must be structured.

**Proving the program has permission to use the API.** The server does not accept requests from just anyone. It requires an API key — a secret string tied to a registered account — in every request. Without it, every call returns a 401 Unauthorised error. This is what **authentication** handles.

These two requirements apply to every AI API — Anthropic, OpenAI, Google, Hugging Face. The format differs slightly between them, but the structure is the same. Understand it once and it applies everywhere.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **REST** | A set of rules for how services communicate over HTTP |
| **Endpoint** | One specific URL that does one specific thing |
| **Base URL** | The root address of an API — e.g. `https://api.anthropic.com` |
| **Request** | Your program asking the server for something |
| **Response** | The server's reply |
| **API key** | A secret string that identifies your account and grants access |
| **Bearer token** | The standard way of passing an API key in an HTTP header |
| **Environment variable** | A value stored in the operating system, not in your code |

---

## What REST Actually Is

REST is not a library or a tool you install. It is a set of conventions — agreed rules about how to structure requests and responses so that any client can talk to any server without knowing its internal details.

Think of it like the postal system. To send a letter, you do not need to know how the sorting office works or which van delivers it. You follow the rules — write the address in the right place, put a stamp on, use the right envelope size — and the letter gets there. REST is the postal system for web services. Follow the rules, and the request reaches the server correctly.

REST is built on top of HTTP — the same protocol a browser uses to load web pages. Every tool you already know for HTTP applies directly to REST APIs.

---

## REST Core Concepts

### Resources and URLs

In REST, everything is a **resource** — something that has a URL. The URL says what you are working with.

For the exam prep chatbot calling the Anthropic API:

```text
Base URL:    https://api.anthropic.com
Endpoint:    /v1/messages
Full URL:    https://api.anthropic.com/v1/messages
```

The base URL is the root address of the API. The endpoint is the specific path for one operation. Together they form the full URL the request goes to.

Different endpoints do different things:

```text
https://api.anthropic.com/v1/messages      → send a message, get a response
https://api.openai.com/v1/embeddings       → convert text to a vector (File 3)
https://api.openai.com/v1/models           → list available models
```

### Statelessness

Every REST request must carry **everything the server needs** to process it. The server keeps no memory of previous requests. Each request is completely independent.

This matters for the chatbot. If a student asks *"Explain cosine similarity"* and then follows up with *"Can you give me an example?"*, the server does not remember the first question. The program must include the full conversation history in every new request.

### HTTP Methods

REST uses HTTP methods to say what kind of action is being taken:

| Method | What it does | When the chatbot uses it |
|---|---|---|
| **GET** | Read a resource | Fetching a list of available models |
| **POST** | Create something or trigger an action | Sending a question to the LLM — always POST |
| **PUT** | Replace a resource entirely | Updating a stored document |
| **DELETE** | Remove a resource | Deleting a conversation |

For AI inference — sending a question and getting an answer — it is almost always **POST**. The Anthropic `/v1/messages` endpoint is POST. The OpenAI chat completions endpoint is POST. The embedding endpoints used in File 3 are also POST.

## Anatomy of a REST Request

A complete REST request has three parts. Think of it like sending a parcel — the address on the outside tells the delivery service where it is going, a label attached says what kind of contents are inside and who sent it, and the box itself holds the actual item. A REST request works the same way: the URL is the address, the headers are the label, and the body is the contents.

Understanding all three makes debugging API calls straightforward.

When a student asks *"What is gradient descent?"*, here is the complete request the chatbot sends:

```text
POST https://api.anthropic.com/v1/messages
│
├── HEADERS (metadata about the request)
│   ├── Content-Type: application/json       ← body is JSON
│   ├── x-api-key: sk-ant-...               ← proves identity
│   └── anthropic-version: 2023-06-01       ← which API version to use
│
└── BODY (the actual data)
    {
      "model": "claude-sonnet-4-6",
      "max_tokens": 1024,
      "system": "You are an exam prep assistant. Answer using the lecture notes provided.",
      "messages": [
        {
          "role": "user",
          "content": "Context: Gradient descent is an optimisation algorithm...\n\nQuestion: What is gradient descent?"
        }
      ]
    }
```

**The URL** — where the request is going.

**The headers** — metadata sent alongside the request. Every POST to an AI API needs at minimum a content type header and an authentication header.

**The body** — the actual payload. For AI APIs this is always JSON. It contains the model to use, any parameters, and the messages to process. Notice the retrieved lecture notes are included in the message content — this is how the chatbot grounds its answer in course material. File 4 covers how those notes are found.

## Anatomy of a REST Response

The server sends back a response with the same structure. Here is what comes back for the gradient descent question:

```text
HTTP/1.1 200 OK
│
├── STATUS CODE: 200 (success)
│
├── HEADERS
│   ├── Content-Type: application/json
│   ├── x-ratelimit-requests-remaining: 47   ← how many requests left (File 2)
│   └── request-id: req_abc123
│
└── BODY
    {
      "id": "msg_abc123",
      "type": "message",
      "role": "assistant",
      "content": [
        {
          "type": "text",
          "text": "Gradient descent is an optimisation algorithm that adjusts a model's parameters step by step to minimise the error in its predictions."
        }
      ],
      "model": "claude-sonnet-4-6",
      "usage": {
        "input_tokens": 87,
        "output_tokens": 32
      }
    }
```

**The status code** — the first thing to check. `200` means success. Anything else means something went wrong. File 2 covers the full error taxonomy.

**The rate limit header** — `x-ratelimit-requests-remaining: 47` tells the chatbot how many requests remain before hitting the limit. The night before the exam when 300 students are using it, this number matters. File 2 covers exactly what to do when it hits zero.

**The body** — `content[0]["text"]` is the generated answer shown to the student. `usage` shows how many tokens were consumed — important for cost tracking.

The other fields in the response body can be ignored for now:

| Field | What it is | Do you need it? |
|---|---|---|
| `id` | A unique ID for this specific request | Only if you need to look up this request later |
| `type` | Always `"message"` for this endpoint | No — it never changes |
| `role` | Always `"assistant"` for the response | No — you already know it is the AI replying |
| `content` | The actual generated text — this is what matters | **Yes — always** |
| `model` | Which model generated the response | Only for logging or debugging |
| `usage` | Token counts — input and output | Yes — for cost tracking |

## Making the Request in Python

```python
import requests

response = requests.post(
    "https://api.anthropic.com/v1/messages",
    headers={
        "Content-Type": "application/json",
        "x-api-key": "sk-ant-YOUR-KEY-HERE",      # never do this in real code
        "anthropic-version": "2023-06-01"
    },
    json={
        "model": "claude-sonnet-4-6",
        "max_tokens": 1024,
        "system": "You are an exam prep assistant. Answer using the lecture notes provided.",
        "messages": [
            {
                "role": "user",
                "content": "Context: Gradient descent adjusts parameters to minimise loss.\n\nQuestion: What is gradient descent?"
            }
        ]
    }
)

print(response.status_code)
data = response.json()
print(data["content"][0]["text"])
```

**Output**

```text
200
Gradient descent is an optimisation algorithm that adjusts a model's parameters step by step to minimise the error in its predictions.
```

This works — but there is a serious problem on line 6. The API key is written directly in the code. This is called **hardcoding**. If this file is pushed to GitHub for a project submission, the key is exposed — permanently, even if the line is deleted in the next commit. The next section explains why this happens and how to fix it.

## Authentication — Proving You Have Permission

### What an API Key Is

An API key is a long, unique secret string tied to an account. When it is included in a request, the server knows:
- Which account is making the request
- What models that account is allowed to use
- What the usage limits are
- Who to bill for the tokens consumed

For the exam prep chatbot, one API key is registered for the project. Every student question goes through that key. If the key is exposed, anyone can use the account — burning through the token budget and running up unexpected charges.

### The Bearer Token Pattern

The standard way to pass an API key is in the `Authorization` header as a **Bearer token**:

```text
Authorization: Bearer sk-ant-YOUR-KEY-HERE
```

"Bearer" simply means "the program carrying this token is allowed in" — like showing a wristband at an event. The wristband does not explain who you are or how you got it. It just proves you are allowed access. The API key works the same way.

Anthropic uses a slightly different header name — `x-api-key` — but the concept is identical. OpenAI uses `Authorization: Bearer`. Most APIs use one or the other. Always check the specific API's documentation.

### Why Hardcoding is Dangerous

```python
# This is dangerous — never do this
api_key = "sk-ant-api03-abc123..."
```

GitHub scans public repositories for exposed API keys and notifies the provider. The provider may revoke the key automatically. Even in a private repository, every team member who has access can see the key.

This happens to students constantly. A project repository is set to public for a portfolio, and within hours the key is found by automated scanners. The key is in the Git history permanently — even deleting the line and committing again does not remove it from history.

## Safe Key Handling

### Option 1 — Environment Variables

An environment variable is a value stored in the operating system, not in the code. The program reads it at runtime.

**Setting it in the terminal:**

On Mac/Linux:
```bash
export ANTHROPIC_API_KEY="sk-ant-YOUR-KEY-HERE"
```

On Windows:
```bash
set ANTHROPIC_API_KEY=sk-ant-YOUR-KEY-HERE
```

**Reading it in Python:**

```python
import os
import requests

api_key = os.environ.get("ANTHROPIC_API_KEY")

if not api_key:
    raise ValueError("ANTHROPIC_API_KEY not set — check your environment")

response = requests.post(
    "https://api.anthropic.com/v1/messages",
    headers={
        "Content-Type": "application/json",
        "x-api-key": api_key,
        "anthropic-version": "2023-06-01"
    },
    json={
        "model": "claude-sonnet-4-6",
        "max_tokens": 1024,
        "system": "You are an exam prep assistant. Answer using the lecture notes provided.",
        "messages": [
            {
                "role": "user",
                "content": "Context: Gradient descent adjusts parameters to minimise loss.\n\nQuestion: What is gradient descent?"
            }
        ]
    }
)

print(response.status_code)
print(response.json()["content"][0]["text"])
```

**Output**

```text
200
Gradient descent is an optimisation algorithm that adjusts a model's parameters step by step to minimise the error in its predictions.
```

The key never appears in the code. If this file is committed to GitHub, the key stays safe on the local machine.

The `if not api_key` check is important — without it, a missing key produces a confusing error deep inside the `requests` call instead of a clear message saying exactly what to fix.

### Option 2 — A .env File with python-dotenv

Setting environment variables in the terminal works but resets when the terminal is closed. A `.env` file stores them permanently on the machine — and `python-dotenv` loads them automatically when the program starts.

**Install python-dotenv:**

```bash
pip install python-dotenv
```

**Create a file called `.env` in the project folder:**

```text
ANTHROPIC_API_KEY=sk-ant-YOUR-KEY-HERE
```

No quotes, no spaces around `=`, one variable per line.

**Load it in Python:**

```python
from dotenv import load_dotenv
import os
import requests

load_dotenv()

api_key = os.environ.get("ANTHROPIC_API_KEY")

response = requests.post(
    "https://api.anthropic.com/v1/messages",
    headers={
        "Content-Type": "application/json",
        "x-api-key": api_key,
        "anthropic-version": "2023-06-01"
    },
    json={
        "model": "claude-sonnet-4-6",
        "max_tokens": 1024,
        "system": "You are an exam prep assistant. Answer using the lecture notes provided.",
        "messages": [
            {
                "role": "user",
                "content": "Context: Gradient descent adjusts parameters to minimise loss.\n\nQuestion: What is gradient descent?"
            }
        ]
    }
)

print(response.json()["content"][0]["text"])
```

**Output**

```text
Gradient descent is an optimisation algorithm that adjusts a model's parameters step by step to minimise the error in its predictions.
```

`load_dotenv()` reads the `.env` file and loads every variable into the environment. The rest of the code reads them with `os.environ.get()` — exactly the same as Option 1. The only difference is where the value is stored.

### The .gitignore File — Keeping .env Out of Git

A `.gitignore` file tells Git which files to never track. The `.env` file must always be in it.

**Create a `.gitignore` in the project folder:**

```text
.env
__pycache__/
*.pyc
```

**Verify it is working:**

```bash
git status
```

If `.env` does not appear in the output — it is correctly ignored. If it does appear — add it to `.gitignore` immediately and do not commit it.

**The order matters:**
1. Create `.gitignore` first
2. Then create `.env`

If `.env` is committed before `.gitignore` is set up, it is already in Git history. Deleting it in a later commit does not remove it from history — the only fix is to revoke the key immediately.

### What to Do If a Key Is Exposed

If the key is accidentally committed to a public repository:

1. Go to the Anthropic Console immediately
2. Revoke the exposed key — deactivates it instantly
3. Generate a new key
4. Update the `.env` file with the new key
5. Check the usage dashboard for unexpected charges

Do not just delete the commit — the key is in Git history and still visible to anyone who clones the repository.

## Putting It Together — The Chatbot's API Function

Here is the complete, safe API call for the exam prep chatbot. This is the function that Files 3 and 4 will feed — they find the right lecture notes, and this function uses them to generate the answer:

```python
from dotenv import load_dotenv
import os
import requests

load_dotenv()

def ask_chatbot(question: str, context: str) -> str:
    # : str means this parameter expects a string
    # -> str means this function returns a string
    # these are optional hints for readability — Python does not enforce them
    """
    Send a student's exam question to the Anthropic API.
    context: the relevant lecture notes retrieved from the vector index (File 4).
    Returns the generated answer as a string.
    """
    api_key = os.environ.get("ANTHROPIC_API_KEY")
    if not api_key:
        raise ValueError("ANTHROPIC_API_KEY not set — check your .env file")

    response = requests.post(
        "https://api.anthropic.com/v1/messages",
        headers={
            "Content-Type": "application/json",
            "x-api-key": api_key,
            "anthropic-version": "2023-06-01"
        },
        json={
            "model": "claude-sonnet-4-6",
            "max_tokens": 1024,
            "system": (
                "You are an exam preparation assistant for a BTech AI programme. "
                "Answer the student's question using only the lecture notes provided. "
                "If the answer is not in the notes, say so clearly rather than guessing."
            ),
            "messages": [
                {
                    "role": "user",
                    "content": f"Lecture notes:\n{context}\n\nQuestion: {question}"
                    # f-string inserts the values of context and question into the text
                    # \n means new line — creates a blank line between the notes and the question
                }
            ]
        }
    )

    response.raise_for_status()
    # raises an exception if the request failed (status 4xx or 5xx)
    # prevents the next line from trying to parse an error message as data
    # covered in full detail in the next file
    return response.json()["content"][0]["text"]


# Test it
question = "What is gradient descent?"
context  = (
    "Gradient descent is an optimisation algorithm used to train machine learning models. "
    "It works by calculating the gradient of the loss function with respect to each parameter, "
    "then adjusting the parameters in the direction that reduces the loss. "
    "This process repeats until the loss is minimised or a stopping condition is met."
)

answer = ask_chatbot(question, context)
print(answer)
```

**Output**

```text
Gradient descent is an optimisation algorithm that trains machine learning models by 
repeatedly adjusting their parameters in the direction that reduces the loss function. 
It calculates the gradient — the direction of steepest increase — and moves in the 
opposite direction, step by step, until the loss is minimised.
```

The context here is hardcoded for testing. In the real chatbot, this context will come from ChromaDB (File 4) — the vector index finds which lecture notes are most relevant to the student's question and passes them to this function automatically.

## Common Mistakes

- **Hardcoding the API key** — if the file is shared or committed to Git, the key is exposed permanently. Always use `os.environ.get()`.
- **Forgetting `load_dotenv()`** — the `.env` file is not loaded automatically. Without this call, `os.environ.get()` returns `None` and the request fails with a confusing error.
- **Creating `.env` before `.gitignore`** — if `.env` is committed even once, it is in Git history. Add `.gitignore` first.
- **Not checking for `None` after `os.environ.get()`** — a missing key produces a cryptic `NoneType` error inside the request call. The explicit `if not api_key` check gives a clear message instead.
- **Forgetting `Content-Type: application/json`** — the server cannot parse the body without it and returns a 400 error.
- **Forgetting `anthropic-version` header** — Anthropic requires this header. Missing it returns a 400.
- **Using `response.json()` without checking `raise_for_status()` first** — if the request failed, the JSON body is an error message, not the expected data structure. Calling `raise_for_status()` before parsing ensures failures are caught cleanly.
