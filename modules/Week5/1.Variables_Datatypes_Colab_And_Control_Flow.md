## What is Python?

Python is a programming language. You write instructions, a program called the **interpreter** reads them one line at a time, runs each one, and shows you the result. That feedback loop — write, run, see result — is what this whole file is about.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Interpreter** | Reads your code and runs it, one line at a time |
| **Interactive mode / REPL** | Type a line, see the result immediately, type the next |
| **Notebook** | A document made of cells where you write and run code |
| **Cell** | A single box in a notebook — holds code or text |
| **Runtime** | The live Python session that remembers what you have run so far |
| **String** | Text in quotes, e.g. `"Hello, world!"` |

## Why Python?

- It reads almost like English. `print("Hello, world!")` does not need much explaining.
- It has a huge collection of ready-made code called **libraries** for AI, data, web apps — almost anything.
- It is the top language globally for AI and data work right now.

## Compiled vs Interpreted

| | Compiled (C, Java) | Interpreted (Python) |
|---|---|---|
| When it is translated | All at once, before running | Line by line, while running |
| Extra file created? | Yes (`.exe`, `.class`) | A `.pyc` bytecode cache, usually hidden |
| Test a quick change | Recompile first | Just run it again |

Python is called an **interpreted language**. In reality, Python first turns your code into **bytecode** and then runs that — but for everyday use it is fine to say "Python is interpreted."

## What is a REPL?

**REPL** = **R**ead, **E**valuate, **P**rint, **L**oop.

```
 ┌──────┐      ┌──────────┐      ┌───────┐
 │ Read │ ───► │ Evaluate │ ───► │ Print │
 └──────┘      └──────────┘      └───┬───┘
     ▲                               │
     └─────────── Loop ◄─────────────┘
```

- **Read**: you type a line of code
- **Evaluate**: Python runs it
- **Print**: the result shows up
- **Loop**: back to Read, ready for your next line

This is exactly what happens in Google Colab — one cell at a time.

## Variables

### What is a Variable?

A **variable** is a name that holds a value — so you can reuse it or change it later, instead of retyping the value everywhere.

You create one with `=`:

```python
x = 5
```

Read this as "`x` now refers to `5`" — not "x equals 5" like in maths. In Python, `=` is an action, not a fact.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Variable** | A name that refers to a value |
| **Assignment (`=`)** | Binds a name to a value |
| **Reassignment** | Giving an existing variable a new value |
| **Identifier** | The name you choose for a variable |
| **Type** | What kind of value it is: number, text, true/false |
| **Dynamic typing** | Python figures out the type for you, automatically |

### Why Variables Matter

Without them, every program can only `print()` fixed text once and forget it. Real programs need to:
- **Remember** a value (a cart total while you keep shopping)
- **Reuse** a value (a tax rate applied to every item)
- **Update** a value (a bank balance after a transaction)

### Reassignment

The same name can point to a new value later. The old one is gone:

```python
score = 100
print(score)

score = 150
print(score)
```

Output:
```
100
150
```

### Naming Rules

- Letters, digits, and `_` only
- Cannot start with a digit: `age2` is fine, `2age` is not
- No spaces or symbols like `-`, `!`, `$`
- Cannot use a **keyword** — a word Python has reserved for its own use

**What is a keyword?** Words like `if`, `for`, `class`, `True`, `and`, `return`. Python uses these to understand the *structure* of your code, so it will not let you use them as variable names.

```python
class = "10A"      # SyntaxError: class is a keyword
class_name = "10A" # fine — just add a word to make it unique
```

You do not need to memorise the full list — Python tells you immediately with a `SyntaxError`.

**Convention (not a rule):** use `snake_case`, like `total_price`, not `TotalPrice`.

Python is **case sensitive**: `total` and `Total` are two different variables.

## The Four Basic Types

```python
customer_name = "Alex Smith"   # str   — text, in quotes
delivery_fee  = 29.50          # float — has a decimal point
order_id      = "SWG10234"     # str   — quoted, even though it has digits
is_paid       = False          # bool  — True or False only
item_count    = 3              # int   — whole number, no decimal
```

Use `type()` to check what kind of data you have:

```python
print(type(customer_name))   # <class 'str'>
print(type(delivery_fee))    # <class 'float'>
print(type(item_count))      # <class 'int'>
print(type(is_paid))         # <class 'bool'>
```

Read `<class 'str'>` simply as "this is a `str`."

| Type | What it stores | Example |
|---|---|---|
| `int` | Whole numbers | `42`, `-5`, `0` |
| `float` | Decimal numbers | `3.14`, `29.5` |
| `str` | Text — anything in quotes | `"hello"`, `"SWG10234"` |
| `bool` | Only two values | `True` or `False` |

---

## Static vs Dynamic Typing

| | Static (Java, C) | Dynamic (Python) |
|---|---|---|
| Declare type up front? | Yes: `int age = 30;` | No — Python figures it out |
| When is type checked? | Before running | While running |
| Can a variable change type? | No | Yes — same name, different type later |

```python
data = 100
print(type(data))   # <class 'int'>

data = "one hundred"
print(type(data))   # <class 'str'>
```

Same name, different type. The type belongs to the **value**, not the name.

## Statements

A **statement** is one complete instruction Python executes. Everything you have written so far — `x = 5`, `print(x)`, `total = price * qty` — is a statement.

- **Assignment statement**: stores a value: `x = 5`
- **Expression statement**: runs and produces a result: `print(x)`

**Two shortcuts worth knowing:**

```python
a = b = 5       # chained assignment: both a and b become 5
x, y = 1, 2     # unpacking: x=1, y=2

x, y = y, x     # swap without a temporary variable
```

Python always evaluates the right-hand side fully first — that is what makes the swap work.

The number of names and values must match, or Python raises an error:

```python
x, y = 1, 2, 3   # ValueError: 2 names, 3 values
```

## Type Conversion

Real data almost always arrives as text. You have to convert it before doing maths with it.

| Function | Converts to | Example | Result |
|---|---|---|---|
| `str(x)` | text | `str(42)` | `"42"` |
| `int(x)` | whole number | `int("5")` | `5` |
| `float(x)` | decimal number | `float("3.14")` | `3.14` |
| `bool(x)` | true/false | `bool(0)` | `False` |

**Two things to watch:**
- `int()` **truncates** — it does not round: `int(3.9)` is `3`, not `4`
- `int("3.14")` raises a `ValueError` — the string must look like a whole number. Use `float()` first if there is a decimal point

```python
"5" + 3          # TypeError: can't add text and a number
int("5") + 3     # 8 — works once converted
```

Python does a little conversion automatically — but only between compatible number types:

```python
print(3 + 4.0)   # 7.0 — int promotes to float automatically
```

It will never convert a `str` to a number on its own — that always needs an explicit function.

## Strings in Depth

### Quotes and Concatenation

Single and double quotes are interchangeable — Python does not care which you use, as long as they match:

```python
name1 = "Alex"
name2 = 'Alex'
```

Use double quotes if your text contains an apostrophe, or single quotes if it contains a double quote:

```python
message = "It's a great day"
quote = 'She said "hello"'
```

**Concatenation** joins strings with `+`:

```python
first = "Chai"
second = "Point"
print(first + second)   # ChaiPoint
```

### Indexing

Pull out one character by its position, starting at `0`:

```python
word = "Python"
print(word[0])    # P
print(word[1])    # y
print(word[-1])   # n — negative counts from the end
```

`-1` is always the last character. Go past the end and Python raises an `IndexError`.

### Slicing

`start:stop:step` pulls out a whole section. **Stop is never included:**

```python
word = "Python"
print(word[0:3])   # Pyt — index 0, 1, 2 (not 3)
print(word[2:])    # thon — from index 2 to the end
print(word[:4])    # Pyth — from the start to index 3
print(word[::2])   # Pto — every 2nd character
print(word[::-1])  # nohtyP — reversed
```

This exact `start:stop:step` syntax works on lists too — once it clicks here, it is already familiar there.

### Common String Methods

Methods are actions you call with a dot. They do not change the original string — they return a **new** one.

| Method | Does what | Example | Result |
|---|---|---|---|
| `.upper()` | ALL CAPS | `"hi".upper()` | `"HI"` |
| `.lower()` | all lowercase | `"HI".lower()` | `"hi"` |
| `.strip()` | removes leading/trailing spaces | `"  hi  ".strip()` | `"hi"` |
| `.replace(a, b)` | swaps text | `"hi".replace("h","H")` | `"Hi"` |
| `.split(sep)` | splits into a list | `"a,b,c".split(",")` | `['a','b','c']` |
| `.join(list)` | joins a list into one string | `"-".join(['a','b'])` | `"a-b"` |
| `len(text)` | length of the string | `len("hi")` | `2` |

```python
raw_input = "  Alex Smith  "
clean_name = raw_input.strip()
print(clean_name.upper())   # ALEX SMITH
```

### Strings Are Immutable

Once created, a string **cannot be changed in place** — every method that "changes" it actually returns a brand-new string:

```python
name = "python"
name[0] = "P"   # TypeError: strings can't be edited like this
```

The fix is always **reassignment**:

```python
name = "python"
name = "P" + name[1:]
print(name)   # Python
```

### Escape Characters

A backslash `\` inside a string means "the next character is special":

| Escape | Means |
|---|---|
| `\n` | new line |
| `\t` | tab |
| `\"` | a literal quote mark inside a double-quoted string |
| `\\` | a literal backslash |

```python
print("Line one\nLine two")
```

Output:
```
Line one
Line two
```

### f-strings — Clean Output

An f-string embeds a value directly in the text using `{}`:

```python
item = "Laptop"
price = 999.99
print(f"{item} costs ${price:.2f}")
```

Output:
```
Laptop costs $999.99
```

- The `f` before the quote makes it an f-string
- `{price:.2f}` means: print `price` with 2 decimal places
- **Forgetting the `f`** prints literal text `{price}` instead of the value

**Common format specifiers:**

| Specifier | Does what | Example | Result |
|---|---|---|---|
| `:.2f` | 2 decimal places | `f"{15:.2f}"` | `15.00` |
| `:d` | plain integer | `f"{7:d}"` | `7` |
| `:>10` | right-align, 10 wide | `f"[{'Tea':>10}]"` | `[       Tea]` |

## Operators and Expressions

### What is an Operator?

An **operator** is a symbol that tells Python to do something with values. An **expression** is any combination of values and operators that reduces to one result.

```python
total = 200 + 50
```

`200 + 50` is the expression, `+` is the operator, `200` and `50` are the **operands**. Python works out `250` first, then stores it in `total`.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Operator** | A symbol that acts on values, e.g. `+`, `==`, `and` |
| **Operand** | A value the operator works on |
| **Expression** | Values + operators that reduce to one result |
| **Truthy / Falsy** | How Python treats any value as true-ish or false-ish |
| **Short-circuit** | Python stops checking once the answer is already known |

### Arithmetic Operators

| Operator | Name | Example | Result |
|---|---|---|---|
| `+` | addition | `7 + 3` | `10` |
| `-` | subtraction | `7 - 3` | `4` |
| `*` | multiplication | `7 * 3` | `21` |
| `/` | true division | `7 / 2` | `3.5` |
| `//` | floor division | `7 // 2` | `3` |
| `%` | modulo (remainder) | `7 % 2` | `1` |
| `**` | exponentiation | `7 ** 2` | `49` |

Two things trip people up:
- `/` **always** returns a `float`, even `6 / 2` → `3.0`, not `3`
- `//` rounds **down**: `-7 // 2` is `-4`, not `-3`

`//` and `%` always pair up — this always holds true:
```
(a // b) * b + (a % b) == a
```

### Comparison Operators

Always produce a `bool` — `True` or `False`:

| Operator | Name | Example | Result |
|---|---|---|---|
| `==` | equal to | `5 == 5` | `True` |
| `!=` | not equal to | `5 != 3` | `True` |
| `<` | less than | `3 < 5` | `True` |
| `>` | greater than | `3 > 5` | `False` |
| `<=` | less or equal | `5 <= 5` | `True` |
| `>=` | greater or equal | `3 >= 5` | `False` |

**`=` vs `==` — the most common beginner mistake:**

| | `=` | `==` |
|---|---|---|
| Does what | Stores a value | Asks a question |
| Result | Nothing — it is an action | Always `True` or `False` |
| Example | `x = 5` | `x == 5` |

You can also chain comparisons: `1 < x < 10` reads exactly like "is x between 1 and 10?"

**One quiet gotcha:** comparing different types is legal, but always `False` — `5 == "5"` is `False`, even though they look the same.

### Logical Operators

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `and` | true only if both sides are true | `True and False` | `False` |
| `or` | true if at least one side is true | `True or False` | `True` |
| `not` | flips a value | `not True` | `False` |

**Short-circuit evaluation:** Python stops the instant it already knows the answer.
- `False and anything` → skips the right side, already `False`
- `True or anything` → skips the right side, already `True`

This matters: if the right side would crash (like a division by zero), it might never even run.

### Truthiness

Python treats every value as true-ish or false-ish — not just actual `True`/`False`.

**Falsy** (short, fixed list): `False`, `0`, `0.0`, `""` (empty string)

**Truthy:** everything else — including the string `"False"` (it is non-empty text, so it is truthy).

```python
coupon_code = ""
has_coupon = bool(coupon_code)
print(has_coupon)   # False — empty string is falsy
```

### Operator Precedence

When an expression has more than one operator, Python follows a fixed order:

```
1. ()              parentheses
2. **              exponentiation
3. -x              unary minus
4. * / // %        multiply/divide family
5. + -             add/subtract
6. == != < > <= >= comparisons
7. not             logical not
8. and             logical and
9. or              logical or
```

- `-2 ** 2` is `-4`, not `4` — `**` binds tighter than the minus sign
- Same-level operators go left to right: `20 / 4 * 2` is `(20 / 4) * 2 = 10.0`

**Do not memorise the ladder.** If the order is not obvious, just add parentheses — they always win.

### Try it Yourself — Operators

An order: 4 items at $15, 2 drinks at $20, plus a $10 packing fee, split between 3 friends:

```python
item_price = 15
item_qty = 4
drink_price = 20
drink_qty = 2
packing_fee = 10
friends = 3

item_total = item_price * item_qty + drink_price * drink_qty
final_bill = item_total + packing_fee
share_per_friend = final_bill // friends
leftover = final_bill % friends

print(f"Total: ${final_bill}")
print(f"Each friend pays: ${share_per_friend}")
print(f"Leftover: ${leftover}")
```

Output:
```
Total: $110
Each friend pays: $36
Leftover: $2
```

**Now add a discount check:** the order qualifies if the bill is at least $100, **and** the customer has a student card, **and** the order is not cancelled:

```python
has_student_card = True
order_cancelled = False

qualifies_by_amount = final_bill >= 100
discount_eligible = qualifies_by_amount and has_student_card and not order_cancelled
print(discount_eligible)   # True
```

Try changing `has_student_card` to `False` and see what happens.

## Control Flow — if / elif / else

### Why Conditionals?

Every program you have written so far runs the exact same lines every time. Real programs need to make choices — show a discount only if the cart total is high enough, block a login if the password is wrong.

A **conditional** lets your code run different lines depending on whether something is `True` or `False`.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Conditional** | Code that runs only if a condition is true |
| **Branch** | One possible path your code can take |
| **Indentation** | The spaces at the start of a line — Python uses this to know what is "inside" a block |
| **Nested conditional** | A conditional written inside another conditional |
| **Ternary expression** | A one-line if/else that produces a value |

### `if`, `elif`, `else`

```python
age = 20

if age >= 18:
    print("You can vote.")
```

Output:
```
You can vote.
```

The colon `:` and the indented line below it are both required. That indented block is what actually runs when the condition is `True`.

**Add an alternative with `else`:**

```python
age = 15

if age >= 18:
    print("You can vote.")
else:
    print("Not old enough yet.")
```

Output:
```
Not old enough yet.
```

**More than two options? Use `elif`** (short for "else if"):

```python
marks = 72

if marks >= 90:
    print("Grade: A")
elif marks >= 75:
    print("Grade: B")
elif marks >= 60:
    print("Grade: C")
else:
    print("Grade: F")
```

Output:
```
Grade: C
```

Python checks each condition top to bottom and runs the **first** one that is `True`, then skips the rest entirely.

### Indentation is Structure, Not Style

In most languages, indentation is just for readability. In Python, it is the actual syntax — it tells Python what belongs inside the `if` block and what does not.

```python
if age >= 18:
    print("You can vote.")      # inside the if block
    print("Welcome!")           # also inside
print("This always runs.")      # outside — not indented
```

**Mismatched indentation breaks your code:**

```python
if age >= 18:
print("You can vote.")   # IndentationError: expected an indented block
```

### Boolean Expressions in Conditions

You already met `and`, `or`, and `not` in the Operators section — conditionals are where they really earn their keep:

```python
age = 20
has_id = True

if age >= 18 and has_id:
    print("Entry allowed.")
else:
    print("Entry denied.")
```

Output:
```
Entry allowed.
```

```python
is_weekend = True
is_holiday = False

if is_weekend or is_holiday:
    print("No classes today.")
```

Output:
```
No classes today.
```

```python
is_banned = False

if not is_banned:
    print("Access granted.")
```

Output:
```
Access granted.
```

Short-circuit evaluation still applies inside `if` conditions.

### Nested Conditionals

An `if` can sit inside another `if` — for decisions that depend on more than one thing:

```python
has_ticket = True
age = 16

if has_ticket:
    if age >= 18:
        print("Entry allowed.")
    else:
        print("Entry allowed with guardian.")
else:
    print("No ticket, no entry.")
```

Output:
```
Entry allowed with guardian.
```

**Two levels of nesting is usually fine. Three or more — consider using `and` instead.** Nesting is easy to write in the moment but harder to read later.

### Conditional (Ternary) Expression

For simple either/or decisions, a one-liner works:

```python
value_if_true if condition else value_if_false
```

```python
age = 20
status = "Adult" if age >= 18 else "Minor"
print(status)
```

Output:
```
Adult
```

This is an **expression** — it produces a value you can store or print directly. Use it for short, simple choices. For anything with more than one condition or multiple actions, a normal `if`/`elif`/`else` block reads better.

### Try it Yourself — Conditionals

**(a)** Canteen entry check — entry requires being a student **or** having a guest pass, **and** not being on the blocklist:

```python

if (is_student or has_guest_pass) and not is_blocked:
    print("Entry allowed.")
else:
    print("Entry denied.")
```

Change `is_blocked` to `True` and predict the output before running.

**(b)** Write a grading program for marks `85` — print `"A"` for 90+, `"B"` for 75+, `"C"` for 60+, and `"F"` otherwise.

**(c)** Rewrite this using a ternary expression:

```python
temperature = 40
if temperature > 35:

else:
    weather = "Pleasant"
print(weather)
```

## Control Flow — Loops

### Why Loops?

Without a loop, printing something 10 times means writing `print()` 10 times. Loops let you repeat code without repeating yourself.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Loop** | Code that repeats |
| **Iteration** | One pass through the loop body |
| **Iterable** | Something you can loop over one item at a time |
| **Infinite loop** | A loop whose condition never becomes `False` — runs forever |
| **`break`** | Exits the loop immediately |
| **`continue`** | Skips the rest of this iteration, moves to the next one |

### `while` Loop

Repeats **as long as** a condition stays `True`:

```python
count = 1

while count <= 5:
    print(count)
    count += 1
```

Output:
```
1
2
3
4
5
```

Every `while` loop needs something that eventually makes the condition `False` — here, `count += 1`. Miss that step and you get an **infinite loop**. If you ever run one by accident in Colab, use **Runtime → Interrupt execution** to stop it.

**A useful pattern — `while True` with a `break`:**

```python
while True:
    answer = input("Type 'quit' to stop: ")
    if answer == "quit":
        break
    print("You typed:", answer)
```

The loop runs until the user types `"quit"`. `break` exits immediately.

### `for` Loop

Repeats **once for each item** in something iterable — a string, a `range()`, or a list:

```python
for letter in "Python":
    print(letter)
```

Output:
```
P
y
t
h
o
n
```

`letter` is the **loop variable** — it takes on each value in turn. You can name it anything, but a descriptive name helps: `for student in ...` reads better than `for x in ...`.

### `range()`

The most common thing to loop over when you just need numbers:

```python
for i in range(5):
    print(i)
```

Output:
```
0
1
2
3
4
```

`range()` counts from `0` up to, **but not including**, the number you give it — same "stop is excluded" rule as slicing.

**`range()` takes up to three arguments:** `range(start, stop, step)`

```python
for i in range(2, 10, 2):   # even numbers from 2 to 8
    print(i)
```

Output:
```
2
4
6
8
```

Count downward:

```python
for i in range(5, 0, -1):
    print(i)
```

Output:
```
5
4
3
2
1
```

**Just need to repeat something N times without caring about the number?** Use `_` as a throwaway variable — a common Python convention:

```python
for _ in range(3):
    print("Hello!")
```

Output:
```
Hello!
Hello!
Hello!
```

### `enumerate()` — Index and Value Together

Sometimes you need both the position and the value while looping:

```python
for index, letter in enumerate("abc"):
    print(index, letter)
```

Output:
```
0 a
1 b
2 c
```

Without `enumerate()`, you would have to track the index yourself with a separate counter variable. `enumerate()` does it for you.

### `zip()` — Pairing Up Two Sequences

`zip()` walks through two iterables at the same time, pairing up matching positions:

```python
names = ["Alex", "Maria", "James"]
scores = [85, 92, 78]

for name, score in zip(names, scores):
    print(name, score)
```

Output:
```
Alex 85
Maria 92
James 78
```

If the two are different lengths, `zip()` stops at the **shorter** one — no error, extra items are simply ignored.

### `break` and `continue`

**`break`** exits the loop immediately:

```python
for i in range(10):
    if i == 5:
        break
    print(i)
```

Output:
```
0
1
2
3
4
```

**`continue`** skips only the rest of the *current* iteration, then moves on to the next:

```python
for i in range(6):
    if i % 2 == 0:
        continue
    print(i)
```

Output:
```
1
3
5
```

### Nested Loops

A loop inside another loop — the inner loop runs completely for every single pass of the outer one:

```python
for row in range(3):
    for col in range(2):
        print(f"row {row}, col {col}")
```

Output:
```
row 0, col 0
row 0, col 1
row 1, col 0
row 1, col 1
row 2, col 0
row 2, col 1
```

Same trade-off as nested conditionals — useful for grids and tables, but readability drops fast past two levels.

### Loops and Conditionals Together

These two tools combine naturally. A loop can contain an `if`:

```python
for i in range(1, 11):
    if i % 2 == 0:
        print(f"{i} is even")
    else:
        print(f"{i} is odd")
```

A `while` loop with an `if` for a user-driven exit:

```python
total = 0
while True:
    entry = input("Enter a number (0 to stop): ")
    number = int(entry)
    if number == 0:
        break
    total += number

print(f"Total: {total}")
```

## Common Mistakes

| Mistake | What happens | Fix |
|---|---|---|
| Forgetting quotes: `print(Hello)` | `NameError` | `print("Hello")` |
| Mixing quote types: `'text"` | `SyntaxError` | Match opening and closing quote |
| Using `=` instead of `==` in a condition | Logic error | `if x == 5:` not `if x = 5:` |
| Missing `:` after `if`, `elif`, `else`, `for`, `while` | `SyntaxError` | Always end these lines with `:` |
| Wrong indentation | `IndentationError` | Use 4 spaces consistently — never mix tabs and spaces |
| `input()` returns a string — forgetting to convert | `TypeError` when doing maths | Use `int()` or `float()` before calculating |
| Infinite `while` loop — forgetting to update the counter | Program hangs | Always update the loop variable inside the loop |
| `range(5)` — expecting it to include 5 | Off-by-one errors | `range(5)` gives `0,1,2,3,4` — stops before 5 |
| Comparing `"5" == 5` expecting `True` | Gets `False` | Convert first: `int("5") == 5` |
| Treating `"False"` as falsy | Logic error | Only the actual `False` value is falsy — any non-empty string is truthy |
| `int("3.14")` | `ValueError` | Use `float("3.14")` first, then `int()` if needed |
| Editing a string directly: `name[0] = "P"` | `TypeError` | Reassign: `name = "P" + name[1:]` |
| Forgetting `f` in an f-string | Prints literal `{price}` | Add `f` before the opening quote |
| Assuming a string method changes the original | No change visible | Store the result: `name = name.strip()` |

## Interview Questions

**Q1: Is Python statically or dynamically typed?**

A: Dynamically typed. You never declare a type up front — Python figures it out from the value. The same name can hold different types at different points.

**Q2: What does `input()` always return?**

A: A `str` — always, no matter what the user typed. Always convert with `int()` or `float()` before doing arithmetic.

**Q3: What is the difference between `=` and `==`?**

A: `=` assigns a value. `==` compares two values and returns `True` or `False`. Using `=` inside a condition is the most common beginner bug.

**Q4: What is the difference between `/` and `//`?**

A: `/` is true division — always returns a `float`. `//` is floor division — rounds down toward negative infinity and returns an `int` if both operands are `int`.

**Q5: Are strings mutable or immutable in Python?**

A: Immutable. Once created, a string cannot be changed — every "changing" method returns a new string instead of editing the original.

**Q6: What is the difference between `if`/`elif` and a series of separate `if` statements?**

A: `elif` only runs if all earlier conditions were `False` and stops at the first match. Separate `if` statements each get checked independently — so more than one could run. This matters when conditions overlap.

**Q7: What is the difference between `break` and `continue`?**

A: `break` exits the loop entirely. `continue` skips only the rest of the current iteration and moves on to the next one.

**Q8: What does `range(2, 10, 2)` produce?**

A: `2, 4, 6, 8` — starts at 2, stops before 10, steps by 2.

**Q9: What is short-circuit evaluation?**

A: Python stops evaluating `and`/`or` the moment the final result is already known — it will not check the right side if the left side already decides the answer.

**Q10: What values are falsy in Python?**

A: A short fixed list: `False`, `0`, `0.0`, and `""`. Everything else is truthy.

## Quick Recap

**Python and Colab:**
- Python is interpreted — it runs line by line. REPL = Read, Evaluate, Print, Loop.
- Colab is a free, browser-based Python environment. Press Shift + Enter to run a cell.
- `print()` displays whatever you give it. Always run the cell after editing.

**Variables and types:**
- A variable is a name bound to a value with `=`. Reassignment replaces the old value.
- Four basic types: `int`, `float`, `str`, `bool`. Use `type()` to check.
- `input()` always returns a `str` — convert with `int()` or `float()` before doing maths.
- Python is dynamically typed and case sensitive.

**Statements and conversion:**
- `int()` truncates — it does not round. `int("3.14")` raises a `ValueError`.
- f-strings (`f"{value:.2f}"`) are the modern way to format output cleanly.
- Comments start with `#` and are ignored by Python.

**Strings:**
- Index with `[n]`, slice with `[start:stop:step]` — stop is always excluded.
- String methods return a **new** string — strings are immutable.
- `[::-1]` reverses a string.

**Operators:**
- `=` assigns, `==` compares — never mix them up.
- `/` gives a float, `//` floors down, `%` gives the remainder.
- `and`, `or`, `not` combine conditions with short-circuit evaluation.
- Falsy values: `False`, `0`, `0.0`, `""`. Everything else is truthy.

**Control flow — if/elif/else:**
- Python checks conditions top to bottom and stops at the first `True` branch.
- Indentation is syntax — it defines what is inside a block.
- A ternary expression is a compact one-line if/else that produces a value.

**Control flow — loops:**
- `while` repeats as long as a condition is `True`. Always ensure something makes it `False`.
- `for` repeats once per item. Use `range(start, stop, step)` for number sequences.
- `enumerate()` gives index and value together. `zip()` pairs two sequences, stopping at the shorter one.
- `break` exits a loop. `continue` skips the rest of the current iteration.
- Nested loops run the inner loop fully for every pass of the outer one.
