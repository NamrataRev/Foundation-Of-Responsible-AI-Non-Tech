# Citation and Grounding

---

## Learning Objectives

By the end of this topic, you should be able to:

- Explain the difference between citation and grounding and why both matter
- Implement in-text citation and an end-of-answer sources section in the exam prep chatbot
- Extract cited source IDs from a generated answer programmatically
- Verify that a generated answer is grounded in the retrieved documents
- Handle the case where the model correctly says it cannot answer from the notes

---

## Overview

The chunking topic produced a more precise retrieval pipeline. Each chunk covers one focused idea. The right chunks are retrieved for each question. The model receives a focused, relevant context.

But a student reading the answer still has one unsolved problem: they cannot tell where the answer came from. The chatbot says "the learning rate controls the size of each parameter update step" — is that from their lecture notes, or did the model add it from general knowledge? If they want to revise further, which note should they open?

**Citation** solves the first problem — it tells the student which specific document each claim came from. The student sees `[ln_003]` next to a statement and knows exactly which lecture note to check.

**Grounding** solves the second — it is the property that ensures the answer actually traces back to the retrieved documents. A cited answer is not automatically grounded. The model might cite `[ln_003]` for a claim that was never in `ln_003`. Grounding requires verification.

This topic covers both: how to get the model to produce cited answers, how to extract and display those citations cleanly, and how to verify that the answer is genuinely grounded in the retrieved content.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **Citation** | A reference in the answer pointing to the source document a claim came from |
| **Grounding** | The property that every claim in the answer traces back to a retrieved document |
| **In-text citation** | A source reference embedded directly in the answer — e.g. `[ln_001]` |
| **Sources section** | A list of cited documents at the end of the answer |
| **Faithfulness** | How well the answer reflects only what the retrieved documents say |
| **Hallucination** | A claim in the answer not supported by any retrieved document |

---

## What Grounding Means

Grounding is not a feature you add — it is a property you verify. An answer is grounded when every claim it makes can be traced back to a specific piece of retrieved content.

Think of it like academic referencing. A well-referenced essay does not just list sources at the end — every claim in the body maps to a specific reference. A poorly referenced essay lists sources but the connection between claims and sources is loose or wrong. The sources section looks correct, but the essay contains claims that came from the writer's memory, not from the cited sources.

The exam prep chatbot has the same risk. The model generates with citation formatting — `[ln_001]`, `[ln_003]` — but those citations may not accurately reflect where each claim came from. Grounding verification checks the connection.

## Step 1 — Getting the Model to Cite Sources

Citation starts in the system prompt. The model needs explicit instructions about how to format citations and what to cite.

### Weak vs Strong Citation Instructions

**Weak instruction — too vague:**

```text
"Use the lecture notes to answer. Mention your sources."
```

The model may cite sources in any format — "according to the notes", "as stated in document 1", or nothing at all.

**Strong instruction — specific format:**

```text
"Answer using only the lecture notes provided. After each sentence or
claim, add the source document ID in square brackets — for example [ln_001].
Every factual claim must have a citation. Do not make any claim that
does not have a source in the provided notes."
```

The model now knows the exact format, knows citations are required for every claim, and knows what to do when a claim has no source — do not make it.

```python
CITATION_SYSTEM_PROMPT = (
    "You are an exam preparation assistant for a BTech AI programme. "
    "Answer the student's question using only the lecture notes provided. "
    "After each sentence that contains a factual claim, add the source "
    "document ID in square brackets — for example [ln_001] or [ma_001]. "
    "Every factual claim must have a citation from the provided notes. "
    "If the notes do not contain enough information to answer the question, "
    "respond with: 'The provided notes do not cover this topic in sufficient "
    "detail. You may want to check: [list what the notes do cover].'"
)
```

### Testing the Citation Prompt

from dotenv import load_dotenv

## Step 2 — Converting Chunk IDs to Document IDs

The citations currently show chunk IDs like `[ln_003_chunk_0]`. This is correct for internal verification — but for display, the student wants to see `[ln_003]`, not an internal chunk reference.

The `source_id` metadata field stored during chunking contains the original document ID. Use it to convert chunk citations to document citations:

```python
import re

def extract_cited_ids(answer: str) -> list:
    """
    Find all citation IDs in square brackets in the answer.
    Returns a list of unique IDs in the order they first appear.
    """
    pattern = r'\[([^\]]+)\]'
    # [^\]]+ matches any characters that are not ]
    # this finds everything between [ and ]

    all_citations = re.findall(pattern, answer)
    seen          = set()
    unique        = []

    for citation in all_citations:
        if citation not in seen:
            seen.add(citation)
            unique.append(citation)

    return unique


def chunk_id_to_doc_id(chunk_id: str) -> str:
    """
    Convert a chunk ID to its source document ID.
    ln_003_chunk_0 → ln_003
    ma_001_chunk_2 → ma_001
    """
    parts = chunk_id.split("_chunk_")
    return parts[0] if len(parts) == 2 else chunk_id


cited_chunk_ids = extract_cited_ids(answer)
cited_doc_ids   = list(dict.fromkeys(
    chunk_id_to_doc_id(cid) for cid in cited_chunk_ids
))
# dict.fromkeys preserves order while removing duplicates

print("Cited chunks:", cited_chunk_ids)
print("Source documents:", cited_doc_ids)
```

**Output**

```text
Cited chunks: ['ln_003_chunk_0', 'ln_003_chunk_1', 'ma_001_chunk_0']
Source documents: ['ln_003', 'ma_001']
```

## Step 3 — Displaying the Answer with a Sources Section

The answer currently embeds citations inline. For the student-facing display, add a clean sources section at the end:

```python
def format_answer_with_sources(answer: str,
                                cited_doc_ids: list,
                                doc_metadata: dict) -> str:
    """
    Replace chunk IDs in the answer with document IDs,
    then append a formatted sources section.

    doc_metadata: dict mapping doc_id to display info
    e.g. {"ln_003": {"title": "Gradient Descent Notes", "type": "lecture_note"}}
    """
    # replace chunk citations with document citations in the answer text
    formatted_answer = re.sub(
        r'\[(\w+)_chunk_\d+\]',
        lambda m: f"[{m.group(1)}]",
        answer
    )
    # \w+ matches the document ID (ln_003, ma_001 etc.)
    # _chunk_\d+ matches the chunk suffix
    # replaces [ln_003_chunk_0] with [ln_003]

    sources_section = "\n\n---\n**Sources:**\n"
    for doc_id in cited_doc_ids:
        meta  = doc_metadata.get(doc_id, {})
        title = meta.get("title", doc_id)
        dtype = meta.get("type", "document")
        sources_section += f"- [{doc_id}] {title} ({dtype})\n"

    return formatted_answer + sources_section


doc_metadata = {
    "ln_003": {"title": "Gradient Descent and Learning Rate", "type": "lecture note"},
    "ma_001": {"title": "2024 Data Science Model Answers",    "type": "model answer"}
}

display_answer = format_answer_with_sources(answer, cited_doc_ids, doc_metadata)
print(display_answer)
```

**Output**

```text
The learning rate controls the size of each parameter update step during
gradient descent [ln_003]. A high learning rate causes the algorithm to
overshoot the minimum [ln_003]. A low learning rate causes very slow
convergence, making training impractically long [ma_001].

---
**Sources:**
- [ln_003] Gradient Descent and Learning Rate (lecture note)
- [ma_001] 2024 Data Science Model Answers (model answer)
```

The student now sees a clean answer with in-text citations and a sources list. They can look up `ln_003` in their notes and verify every claim.

## Step 4 — Verifying Grounding

Citation tells the student where each claim came from. Grounding verification checks whether those citations are accurate — whether the claimed source actually supports the claimed fact.

As shown in the hallucination topic, the model can cite the wrong source even when the content is correct. Verification catches this.

```python
def verify_grounding(answer: str, context: str) -> dict:
    """
    Ask the model to check whether each claim in the answer
    is explicitly supported by the retrieved context.

    Returns a dict with:
    - supported: list of claims that are grounded
    - unsupported: list of claims that are not grounded
    - verdict: "grounded" or "ungrounded"
    """
    response = requests.post(
        "https://api.anthropic.com/v1/messages",
        headers={
            "Content-Type": "application/json",
            "x-api-key": os.environ.get("ANTHROPIC_API_KEY"),
            "anthropic-version": "2023-06-01"
        },
        json={
            "model": "claude-sonnet-4-6",
            "max_tokens": 512,
            "system": (
                "You are a grounding verifier. Given a generated answer and "
                "the source notes it was based on, check each factual claim "
                "in the answer against the notes. "
                "Respond in this exact format:\n"
                "SUPPORTED: [list each claim that is directly supported]\n"
                "UNSUPPORTED: [list each claim not found in the notes, "
                "or 'None' if all claims are supported]\n"
                "VERDICT: grounded or ungrounded"
            ),
            "messages": [
                {
                    "role": "user",
                    "content": (
                        f"Source notes:\n{context}\n\n"
                        f"Generated answer:\n{answer}"
                    )
                }
            ]
        }
    )

    result_text = response.json()["content"][0]["text"]

    supported   = []
    unsupported = []
    verdict     = "unknown"

    for line in result_text.split("\n"):
        if line.startswith("SUPPORTED:"):
            supported = [s.strip() for s in
                         line.replace("SUPPORTED:", "").split(",")]
        elif line.startswith("UNSUPPORTED:"):
            raw = line.replace("UNSUPPORTED:", "").strip()
            unsupported = [] if raw.lower() == "none" else [raw]
        elif line.startswith("VERDICT:"):
            verdict = line.replace("VERDICT:", "").strip().lower()

    return {
        "supported":   supported,
        "unsupported": unsupported,
        "verdict":     verdict
    }


result = verify_grounding(answer, context)
print("Verdict:", result["verdict"])
print("Unsupported claims:", result["unsupported"])
```

**Output** (when the answer is fully grounded):

```text
Verdict: grounded
Unsupported claims: []
```

**Output** (when the model added content beyond the notes):

```text
Verdict: ungrounded
Unsupported claims: ['A high learning rate causes the loss to diverge completely']
```

When grounding fails, the chatbot can either return the answer with a warning or regenerate without the unsupported claim.

### Faithfulness Score

Beyond a pass/fail grounding verdict, a **faithfulness score** measures what proportion of claims in the answer are supported by the retrieved context. It gives a 0–1 number — 1.0 means every claim is grounded, 0.0 means nothing is.

```python
def faithfulness_score(answer: str, context: str) -> float:
    """
    Ask the model to count total claims and supported claims.
    Returns a score from 0.0 (no grounding) to 1.0 (fully grounded).
    """
    response = requests.post(
        "https://api.anthropic.com/v1/messages",
        headers={
            "Content-Type": "application/json",
            "x-api-key": os.environ.get("ANTHROPIC_API_KEY"),
            "anthropic-version": "2023-06-01"
        },
        json={
            "model": "claude-sonnet-4-6",
            "max_tokens": 256,
            "system": (
                "You are a grounding evaluator. Count the number of factual "
                "claims in the answer. Then count how many of those claims "
                "are explicitly supported by the source notes. "
                "Respond in this exact format:\n"
                "TOTAL_CLAIMS: <number>\n"
                "SUPPORTED_CLAIMS: <number>"
            ),
            "messages": [
                {
                    "role": "user",
                    "content": f"Source notes:\n{context}\n\nAnswer:\n{answer}"
                }
            ]
        }
    )

    text  = response.json()["content"][0]["text"]
    total = supported = 0

    for line in text.split("\n"):
        if line.startswith("TOTAL_CLAIMS:"):
            total = int(line.split(":")[1].strip())
        elif line.startswith("SUPPORTED_CLAIMS:"):
            supported = int(line.split(":")[1].strip())

    return supported / total if total > 0 else 0.0


score = faithfulness_score(answer, context)
print(f"Faithfulness score: {score:.2f}")
# 1.0 = fully grounded
# 0.8 = 80% of claims are grounded — 1 in 5 may be hallucinated
# 0.5 = half the claims are ungrounded — answer needs review
```

**Output**

```text
Faithfulness score: 1.00
```

A threshold of 0.8 or above is a practical minimum for a trustworthy answer. Below 0.8, the answer should be flagged for review or regenerated.

### What to Show the Student When Grounding Fails

When the grounding verdict is "ungrounded" or the faithfulness score is below threshold, the developer sees a warning — but the student still needs a response. Three options:

**Option 1 — Show the answer with a warning banner:**
```python
def student_response(answer: str, score: float, threshold: float = 0.8) -> str:
    if score >= threshold:
        return answer
    return (
        "⚠️ Note: parts of this answer may go beyond your lecture notes. "
        "Please verify against your materials before relying on it.\n\n"
        + answer
    )
```

**Option 2 — Regenerate with a stricter prompt:**
```python
if score < 0.8:
    stricter_prompt = CITATION_SYSTEM_PROMPT + (
        " You MUST only use information explicitly stated word-for-word "
        "in the provided notes. Do not paraphrase or infer."
    )
    answer = generate(question, context, system=stricter_prompt)
```

**Option 3 — Return only the grounded claims:**
Strip the unsupported sentences from the answer and return only the verified content with a note that partial information was found.

For the exam prep chatbot, **Option 1** is the most practical — it is transparent with the student, fast, and does not require an additional API call.

When the retrieved notes do not contain enough information to answer the question, the model should say so clearly — not guess.

The system prompt already handles this: *"If the notes do not contain enough information, respond with: 'The provided notes do not cover this topic in sufficient detail.'"*

But the chatbot should also verify that this response is itself grounded — that the model is not incorrectly claiming the notes are silent on a topic they actually cover.

```python
def is_no_answer_response(answer: str) -> bool:
    """
    Check whether the model returned a no-answer response
    rather than a factual answer.
    """
    no_answer_indicators = [
        "do not cover",
        "not covered",
        "no information",
        "cannot find",
        "not in the notes"
    ]
    answer_lower = answer.lower()
    return any(indicator in answer_lower for indicator in no_answer_indicators)


def handle_no_answer(answer: str, retrieved_docs: list) -> str:
    """
    If the model says it cannot answer, but documents were retrieved,
    show the student what the notes do say — they may find it useful
    even if it does not directly answer the question.
    """
    if is_no_answer_response(answer) and retrieved_docs:
        closest = retrieved_docs[0]
        return (
            f"{answer}\n\n"
            f"The closest content found in your notes:\n"
            f"[{closest['id']}] {closest['text'][:300]}..."
        )
    return answer
```

## The Complete Citation Pipeline

```python
from sentence_transformers import SentenceTransformer
from dotenv import load_dotenv
import chromadb, os, requests, re

load_dotenv()

embed_model = SentenceTransformer("all-MiniLM-L6-v2")
client      = chromadb.PersistentClient(path="./exam_prep_db")
collection  = client.get_or_create_collection("exam_prep_chunks")

SIMILARITY_THRESHOLD = 0.8

doc_metadata = {
    "ln_001": {"title": "Gradient Descent Notes",          "type": "lecture note"},
    "ln_002": {"title": "Backpropagation Notes",           "type": "lecture note"},
    "ln_003": {"title": "Learning Rate and Convergence",   "type": "lecture note"},
    "ma_001": {"title": "2024 Data Science Model Answers", "type": "model answer"},
    "pp_001": {"title": "2024 Data Science Past Paper",    "type": "past paper"}
}

def retrieve(question: str, n: int = 3) -> list:
    vec     = embed_model.encode([question]).tolist()
    results = collection.query(query_embeddings=vec, n_results=n)
    docs    = []
    for i in range(len(results["documents"][0])):
        docs.append({
            "id":       results["ids"][0][i],
            "text":     results["documents"][0][i],
            "metadata": results["metadatas"][0][i],
            "distance": results["distances"][0][i]
        })
    return [d for d in docs if d["distance"] < SIMILARITY_THRESHOLD]

def augment(retrieved: list) -> str:
    if not retrieved:
        return ""
    sorted_docs = sorted(retrieved, key=lambda x: x["distance"])
    return "\n\n".join(f"[{d['id']}] {d['text']}" for d in sorted_docs)

def generate(question: str, context: str) -> str:
    if not context:
        return "No relevant lecture notes found for this question."
    response = requests.post(
        "https://api.anthropic.com/v1/messages",
        headers={"Content-Type": "application/json",
                 "x-api-key": os.environ.get("ANTHROPIC_API_KEY"),
                 "anthropic-version": "2023-06-01"},
        json={
            "model": "claude-sonnet-4-6",
            "max_tokens": 1024,
            "temperature": 0.1,
            "system": CITATION_SYSTEM_PROMPT,
            "messages": [{"role": "user",
                          "content": f"Lecture notes:\n{context}\n\nQuestion: {question}"}]
        }
    )
    response.raise_for_status()
    return response.json()["content"][0]["text"]

def extract_and_format(answer: str) -> str:
    cited_chunks = re.findall(r'\[([^\]]+)\]', answer)
    cited_docs   = list(dict.fromkeys(
        c.split("_chunk_")[0] for c in cited_chunks
    ))
    formatted    = re.sub(r'\[(\w+)_chunk_\d+\]',
                          lambda m: f"[{m.group(1)}]", answer)
    sources      = "\n\n---\n**Sources:**\n"
    for doc_id in cited_docs:
        meta     = doc_metadata.get(doc_id, {})
        sources += f"- [{doc_id}] {meta.get('title', doc_id)} ({meta.get('type', '')})\n"
    return formatted + sources

# ── Full pipeline ────────────────────────────────────────────────────
question  = "What is the role of the learning rate in gradient descent?"
retrieved = retrieve(question)
context   = augment(retrieved)
answer    = generate(question, context)
grounding = verify_grounding(answer, context)

if grounding["verdict"] == "ungrounded":
    print("Warning: answer contains unsupported claims:")
    for claim in grounding["unsupported"]:
        print(f"  - {claim}")
else:
    print(extract_and_format(answer))
```

**Output**

```text
The learning rate controls the size of each parameter update step
during gradient descent [ln_003]. A high learning rate causes the
algorithm to overshoot the minimum [ln_003]. A low learning rate causes
very slow convergence [ma_001].

---
**Sources:**
- [ln_003] Learning Rate and Convergence (lecture note)
- [ma_001] 2024 Data Science Model Answers (model answer)
```

## Best Practices

- Always specify the citation format explicitly in the system prompt — vague instructions produce inconsistent formatting
- Convert chunk IDs to document IDs before displaying to the student — internal chunk IDs are not meaningful to them
- Run grounding verification on answers that will be seen by many students — catching one hallucinated claim is worth the extra API call
- Include a sources section at the end of every answer — in-text citations help the student follow reasoning, the sources section makes the full list easy to scan
- Handle the no-answer case explicitly — a model that admits it cannot answer from the notes is more trustworthy than one that guesses

## Common Beginner Mistakes

- **Vague citation instructions** — "mention sources" produces inconsistent formats. The system prompt must specify the exact format: `[doc_id]` after each claim
- **Displaying chunk IDs to students** — `[ln_003_chunk_0]` is an internal identifier. Convert to `[ln_003]` before display
- **Skipping grounding verification** — the model can produce correct content with wrong citations, or hallucinated content that looks cited. Verification is not optional for a trustworthy chatbot
- **No handling for the no-answer case** — when the notes do not cover a question, the model needs an explicit instruction about what to do. Without it, it guesses

---

## Key Takeaways

- **Citation** tells the student where each claim came from — implemented through an explicit system prompt instruction specifying the exact format
- **Grounding** is the property that every claim traces back to a retrieved document — verified through a separate verification step after generation
- Chunk IDs must be converted to document IDs before display — use the `source_id` metadata stored during chunking
- A clean answer includes both in-text citations and an end-of-answer sources section
- Grounding verification uses the model to check the model — it catches the most obvious hallucinations but is not perfect
- When the model correctly says the notes do not cover a topic, show the student the closest retrieved content anyway — it may still be useful

> **Interview tip:** If asked "how do you make a RAG system trustworthy?" — describe both citation and grounding as distinct concepts. Citation is what you see in the answer. Grounding is whether those citations are accurate. Explain the verification step — using the model to check its own output — and mention that it is not perfect but catches the most obvious failures. Most candidates describe citation only. Knowing that grounding requires a separate verification step — and being able to describe how to implement it — shows production-level thinking.
