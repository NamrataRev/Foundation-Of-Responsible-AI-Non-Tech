# Common Failure Modes

---

## Learning Objectives

By the end of this topic, you should be able to:

- Identify the three most common RAG failure modes in Pinecone Assistant
- Deliberately reproduce each failure mode as a controlled experiment
- Diagnose which stage of the pipeline caused each failure
- Apply the correct fix for each failure mode in Pinecone

---

## Overview

The How RAG Hallucinates topic showed five specific hallucination patterns and how to diagnose them from the answer alone. This topic is more practical — it covers the three most common failure modes that occur in real RAG pipelines, shows exactly how to reproduce each one in Pinecone, and explains how to fix them.

The three failure modes are:

- **Bad chunking** — documents are split in a way that breaks meaning and returns incomplete or irrelevant content
- **Wrong embeddings** — the semantic search returns chunks that are topically related but do not actually answer the question
- **Missing citations** — the answer is generated without source references, making it impossible to verify

Each one is a controlled experiment. You set up the failure, observe what breaks, identify which pipeline stage failed, and apply the fix.

---

## Failure Mode 1 — Bad Chunking

### What It Is

Bad chunking happens when a document is split at the wrong points — cutting a sentence in half, separating a concept from its explanation, or grouping unrelated content into the same chunk. The retrieved chunk contains only part of the answer — or contains so much irrelevant content that the relevant part is buried.

### What the Student Sees

The answer is incomplete, cuts off mid-explanation, or gives a partial definition that leaves the student more confused than before.

### How to Reproduce It in Pinecone

Upload a document that has no clear structure — no headings, no paragraph breaks, just a continuous wall of text. Pinecone will split it at arbitrary points and some chunks will cut mid-sentence.

**Steps:**
1. Create a text file where all your notes are merged into one paragraph with no line breaks
2. Upload it to Pinecone Assistant
3. Ask a specific question — for example "What is a while loop?"
4. Observe that the answer may be cut off or start in the middle of a concept

### What the Answer Looks Like

```text
Student: "What is a while loop?"

Answer: "...not a fixed number of times. [Source 1] The condition
must eventually become False otherwise the loop runs forever [Source 1]."

The answer starts mid-sentence. The chunk was cut in the middle
of the explanation — the beginning of the definition is in a
different chunk that was not retrieved.
```

### Which Stage Failed

**Retrieve stage** — the chunks were created badly during the upload phase. The right document was found but the retrieved chunk does not contain the complete answer.

### How to Fix It in Pinecone

**Fix 1 — Structure the document before uploading**
Add clear headings and paragraph breaks to the document. Pinecone splits at natural boundaries — headings and paragraph breaks — when they are present. One concept per paragraph, one topic per section.

**Fix 2 — Split the document into smaller files**
Instead of one large file covering ten topics, upload ten smaller files — one per topic. Each file produces focused chunks that cover one idea completely.

**Fix 3 — Ask a more specific question**
If the chunk is cut mid-sentence, the student may be able to retrieve the missing part by asking a more specific follow-up question that targets the beginning of the concept.

## Failure Mode 2 — Wrong Embeddings

### What It Is

Wrong embeddings happen when the semantic search retrieves chunks that are topically related to the question but do not actually contain the answer. The embedding vectors are similar in meaning — both are about the same general topic — but the specific content the student needs is in a different chunk.

This is different from bad chunking. The chunks are well-formed. The document is well-structured. The problem is that the question and the answer use different vocabulary — so the similarity score is lower for the right chunk than for a related but less relevant one.

### What the Student Sees

The answer is about the right general topic but misses the specific point. It explains something adjacent to what was asked rather than answering directly.

### How to Reproduce It in Pinecone

Ask a question using vocabulary that is different from how the notes express the same concept.

**Steps:**
1. Find a concept in your notes that has a technical name — for example "gradient descent"
2. Ask the question using casual language — "how does the algorithm learn from its mistakes?"
3. The semantic search may retrieve chunks about learning rate or loss functions rather than gradient descent directly

### What the Answer Looks Like

```text
Student: "How does the algorithm learn from its mistakes?"

Notes contain: "Gradient descent minimises the loss function by
adjusting parameters in the direction of steepest descent."

Answer retrieved instead: "The learning rate controls how large
each adjustment step is [Source 1]. A high learning rate causes
overshooting [Source 2]."

The answer is about learning rate — related, but not the direct
explanation of how gradient descent works. The casual phrasing
"learn from mistakes" matched learning-related chunks rather
than the gradient descent definition chunk.
```

### Which Stage Failed

**Retrieve stage** — the right document exists in Pinecone but the similarity score between the question vector and the correct chunk vector was lower than for related chunks. The wrong chunk won the similarity comparison.

### How to Fix It in Pinecone

**Fix 1 — Ask using the exact terminology from the notes**
If the notes say "gradient descent", ask "what is gradient descent?" rather than "how does the algorithm adjust?" The closer the question vocabulary is to the notes vocabulary, the higher the similarity score for the right chunk.

**Fix 2 — Add a glossary file**
Upload a small separate file that maps casual language to technical terms — "learning from mistakes = gradient descent". This gives Pinecone a bridge between the student's natural language and the notes' technical language.

**Fix 3 — Ask a follow-up question**
If the first answer is adjacent but not direct, ask a follow-up that uses the technical term from the first answer: "explain gradient descent specifically."

## Failure Mode 3 — Missing Citations

### What It Is

Missing citations happen when the answer is generated without `[Source N]` references — or with fewer citations than expected. This means the student cannot verify where each claim came from. The answer may be correct, partially correct, or hallucinated — but there is no way to check.

### What the Student Sees

A well-formatted answer with no citation numbers. Or an answer where some sentences have citations and others do not — the uncited sentences are the ones to be suspicious of.

### How to Reproduce It in Pinecone

Clear the Assistant instructions box and ask a question.

**Steps:**
1. Open your Pinecone Assistant
2. Select all the text in the **Assistant instructions** box and delete it — leave it empty
3. Ask any question from your uploaded notes
4. The answer may still have some Pinecone-generated citations but will lack the explicit per-claim citation format

### What the Answer Looks Like

```text
With instructions (correct):
"A while loop repeats as long as a condition stays True [Source 1].
It is used when you do not know in advance how many times to repeat [Source 1]."

Without instructions (missing citations):
"A while loop repeats as long as a condition stays True. It is
used when you do not know in advance how many times to repeat.
The most common use case is reading user input until a quit
command is entered."

The last sentence has no citation — it came from general training,
not the uploaded notes. Without the citation instruction, the model
did not flag where that sentence came from.
```

You already saw this in the RAG Failure and Recovery topic — the screenshot showed an answer generated with the Assistant instructions box empty.

### Which Stage Failed

**Generate stage** — the retrieval worked correctly, the right chunks were in the context. But without the system prompt instruction to cite sources, the model generated the answer freely — mixing retrieved content with general training without marking which was which.

### How to Fix It in Pinecone

**Fix — Restore the Assistant instructions**

Paste this back into the Assistant instructions box:

```text
You are an exam preparation assistant for a BTech AI programme.
Answer the student's question using only the lecture notes provided.
After each factual claim cite the source in square brackets — for example [Source 1].
If the notes do not contain enough information to answer the question,
say so clearly rather than guessing.
```

The citation instruction is what forces the model to attribute every claim to a specific chunk. Without it, the model generates freely.

**Additional fix — make the citation instruction stronger:**

If citations still appear inconsistently even with instructions, add this line:

```text
Every single sentence that contains a factual claim must end with
a citation. A sentence without a citation is not acceptable.
```

## The Three Failure Modes — Side by Side

| Failure Mode | Stage | What breaks | What the student sees | Fix |
|---|---|---|---|---|
| **Bad chunking** | Retrieve | Chunks cut mid-sentence or mix unrelated content | Incomplete or cut-off answers | Structure document with headings; split into smaller files |
| **Wrong embeddings** | Retrieve | Similar but incorrect chunks retrieved | Adjacent topic answered instead of the specific question | Use exact terminology from the notes; add a glossary file |
| **Missing citations** | Generate | No source references in the answer | Answer cannot be verified | Restore Assistant instructions with citation requirement |

## The Experiment — Breaking and Fixing All Three

Work through each failure mode as a controlled experiment using your golden dataset questions:

**Experiment 1 — Bad chunking:**
1. Merge all your notes into one unstructured paragraph file
2. Upload it and ask 3 questions from your golden dataset
3. Record the answers — note which are incomplete or cut off
4. Fix: re-upload with proper headings and paragraph breaks
5. Ask the same 3 questions again — compare the answers

**Experiment 2 — Wrong embeddings:**
1. Take 3 questions from your golden dataset
2. Rephrase each using casual language instead of technical terms
3. Compare the answers to your verified correct answers
4. Fix: ask using the exact terminology from the notes
5. Record whether the correct chunk was retrieved this time

**Experiment 3 — Missing citations:**
1. Clear the Assistant instructions box
2. Ask 3 questions from your golden dataset
3. Record which sentences have no citation
4. Fix: restore the Assistant instructions
5. Ask the same questions — confirm citations appear on every claim

After all three experiments, record your findings in a table:

| Experiment | Question asked | What broke | Which stage | Fix applied | Fixed? |
|---|---|---|---|---|---|
| Bad chunking | "What is a while loop?" | Answer cut mid-sentence | Retrieve | Added headings to document | Yes |
| Wrong embeddings | "How does code repeat?" | Learning rate answered instead | Retrieve | Asked "what is a for loop?" | Yes |
| Missing citations | "What is a while loop?" | No [Source N] in answer | Generate | Restored instructions | Yes |

## Best Practices

- Always reproduce a failure deliberately before trying to fix it — guessing the cause without evidence often leads to fixing the wrong thing
- Run your full golden dataset after each fix, not just the question that failed — a fix for one failure mode sometimes introduces a different one
- Document the before and after answers side by side — the comparison is what shows whether the fix worked
- Fix one thing at a time — if you restructure the document and restore the instructions simultaneously, you will not know which change fixed the problem

## Common Beginner Mistakes

- **Confusing bad chunking with wrong embeddings** — both show up as the wrong content in the answer, but the cause is different. Bad chunking means the chunk itself is broken. Wrong embeddings means the right chunk exists but a different one scored higher. Check the chunk in the citation popup — if it is cut off, bad chunking. If it is complete but about a different aspect, wrong embeddings.
- **Restoring the instructions but not checking all questions** — citations may reappear for simple questions but still be missing for complex multi-part questions. Always run the full golden dataset.
- **Uploading a restructured document without deleting the old one** — Pinecone searches all uploaded files. If the old unstructured version is still there, it will still produce bad chunks. Delete the old file before uploading the restructured version.

---

## Key Takeaways

- The three most common RAG failure modes are bad chunking, wrong embeddings, and missing citations
- Bad chunking and wrong embeddings both appear at the Retrieve stage — but have different causes and different fixes
- Missing citations appear at the Generate stage — caused by a missing or weak system prompt
- Each failure mode is diagnosed by checking the citation popup and comparing the chunk against the answer
- The experiment approach — break deliberately, observe, fix, compare — is the most reliable way to understand what went wrong

> **Interview tip:** If asked "what are common RAG failure modes and how would you fix them?" — name all three, identify which pipeline stage each belongs to, and describe one fix for each. Most candidates name hallucination as the only failure mode. Distinguishing bad chunking from wrong embeddings — both Retrieve stage failures with different causes — shows you understand the pipeline at a diagnostic level.
