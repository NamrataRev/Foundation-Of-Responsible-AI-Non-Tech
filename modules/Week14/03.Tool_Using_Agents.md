## Overview

The previous topic built a fixed pipeline — three nodes in a defined sequence that always runs the same way. The question → Pinecone → Claude path never changes. This predictability is what makes it safe for professional use.

But some tasks do not have a fixed sequence. A civil engineer reviewing a full project brief cannot know in advance exactly which IS codes will be needed until they read the brief. The task requires flexibility — read the brief, decide what to look up, look it up, decide if more is needed, look that up too, then produce the output.

This is what a **tool-using agent** does. Instead of following a fixed path, the agent reads the task, decides which tool to use next, uses it, reads the result, and decides what to do next — until it determines the task is complete.

This topic explains the concept, shows how to add an AI Agent node to the pipeline built in the previous topic, and covers the specific failure modes that agents introduce.

---

## What Makes an Agent Different

The fixed pipeline from the previous topic had one decision point — the engineer typed a question. After that, the sequence was automatic and unchanging.

An agent has a decision point after every step.

```text
FIXED PIPELINE (previous topic):
Question → Pinecone → Claude → Answer
The path never changes. Every question follows the same route.

TOOL-USING AGENT:
Task received
    ↓
Agent decides: "I need to read the project brief first"
→ uses document reading tool
    ↓
Agent decides: "The brief mentions seismic zone III — I need IS 1893"
→ uses Pinecone query tool
    ↓
Agent decides: "IS 1893 references IS 456 for foundation design"
→ uses Pinecone query tool again (this was not planned in advance)
    ↓
Agent decides: "I have enough information to answer"
→ produces output
```

The same Pinecone query tool was used twice — but the second use was not planned. The agent decided it was needed based on what it found in the first query. This is the fundamental difference: the agent's path through the task depends on what it discovers along the way.

## The Four Tools an Agent Can Use in n8n

In n8n's AI Agent node, the agent has access to a set of tools you define. The agent chooses which tool to use and when. The four most relevant for a domain knowledge assistant are:

### Tool 1 — Vector Store Query (Pinecone)

Searches the uploaded knowledge base for relevant chunks. This is the same Pinecone query the fixed pipeline uses — but now the agent decides when to call it and with what query, rather than being called automatically for every question.

**When the agent uses it:** when it needs to find information from the uploaded IS codes or course notes.

### Tool 2 — Document Reader

Reads the full content of an uploaded file. Unlike Pinecone which searches by similarity, the document reader retrieves the complete content of a specific file.

**When the agent uses it:** when a task requires reading a complete project brief, specification document, or reference file from beginning to end.

### Tool 3 — Calculator

Performs mathematical calculations. The fixed pipeline was explicitly told not to calculate — it retrieved the formula and left calculation to the engineer. An agent with a calculator tool can perform the calculation itself.

**When the agent uses it:** when a retrieved IS code formula can be applied with values the agent has already found. For example, if the project brief specifies column dimensions and the IS code gives the formula, the agent can calculate the result.

> ⚠️ **For high-stakes structural calculations:** even when the agent has a calculator tool, a licensed engineer must verify the result. The calculator tool reduces manual effort — it does not replace professional verification.

### Tool 4 — Web Search

Searches the internet for current information not in the uploaded knowledge base.

**When the agent uses it:** when asked about information not in the uploaded IS codes — for example, the latest BIS publication date for a standard, or current material prices.

> ⚠️ **Domain-specific caution:** web search returns general information, not course-specific content. For exam preparation or IS code reference, web search should be disabled to keep answers grounded in uploaded documents only.

## Adding an AI Agent Node in n8n

### Step 1 — Open the Existing Pipeline

Go to your `civil-engineering-rag-pipeline` workflow in n8n. You should have the three-node pipeline from the previous topic:

```text
[Manual Trigger] → [Pinecone Vector Store] → [Message a model]
                          ↑
                   [Embeddings Cohere]
```

For the agent build, we will create a **separate workflow** rather than modifying the working pipeline. This keeps the fixed pipeline intact for comparison in File 4.

Click **Overview** in the left panel → **Create workflow** → name it `civil-engineering-agent`

---

### Step 2 — Add the Manual Trigger

Same as before — click **Add first step** → **Trigger manually**

---

### Step 3 — Add the AI Agent Node

1. Click the **+** on the right side of the Manual Trigger
2. Search for **AI Agent**
3. Select **AI Agent** from the results

![n8n node selector showing AI Agent option at the top — Generates an action plan and executes it, can use external tools](../images/n8n_09_agent_node.jpg)

The AI Agent node opens. This node is different from all previous nodes — instead of one fixed operation, it has:
- A **Prompt** field — the task you give the agent
- A **Tools** section — the tools the agent can choose from
- A **Chat Model** sub-node — the AI model making the decisions

---

### Step 4 — Configure the Agent

**Connect the Chat Model:**
1. Click the **+** below the AI Agent node (the Chat Model* connector)
2. Search for **Anthropic Chat Model**
3. Select it — connect your Gateway credits credential
4. Set model to **claude-sonnet-4-6**

**Set the Agent Prompt:**
In the Prompt field type:
```text
You are a civil engineering standards reference assistant.
You have access to a Pinecone knowledge base containing IS codes
and course notes.

When given a task:
1. Search the knowledge base for relevant IS code clauses
2. If a clause references another standard, search for that too
3. Provide a cited answer showing which IS code clause supports each claim
4. If calculation is needed, use the calculator tool with the formula
   from the IS code

Task: {{ $json.query }}
```

**Add the Pinecone Tool:**
1. Click the **+** in the Tools section of the AI Agent node
2. Search for **Pinecone Vector Store**
3. Select **Retrieve documents for AI Agent as Tool**
4. Connect the same Pinecone index (`rag-docs`) and Cohere embedding model

![n8n canvas showing AI Agent node with Anthropic Chat Model connected below as sub-node and Pinecone Vector Store connected as Tool on the right](../images/n8n_10_agent_configured.jpg)

---

### Step 5 — Run the Agent

Add a test query to the Manual Trigger:
```json
{
  "query": "What IS codes apply to a reinforced concrete column in seismic zone III?"
}
```

Click **Execute workflow** and watch the agent work.

Unlike the fixed pipeline where you saw three nodes light up in sequence, the agent node shows its **reasoning steps** in the output — you can see each tool call the agent made, what query it formulated, and its final response.

![n8n AI Agent node showing reasoning steps in the output — agent ran for 9.9 seconds using 2,616 tokens, called Pinecone tool, formulated its own search query, and explained what it found](../images/n8n_11_agent_output.jpg)

Notice what the output shows: the agent formulated its own search query — **"IS codes for reinforced concrete column design seismic zone III"** — rather than using the exact words from the question. This is the agent deciding how to search, not just passing the question through. The agent also explains its reasoning in the output, including when tools fail and why.

## The Four Agent Failure Modes

Agents introduce failure modes that fixed pipelines do not have. Understanding these is essential before deploying an agent in a professional context.

### Failure Mode 1 — Tool Misuse

The agent calls a tool in a way that produces a result but not the right one.

**Example:** the agent searches Pinecone with the query "seismic zone" when it should search for "IS 1893 earthquake resistant design." The search returns results but they are too broad — the agent builds its answer on loosely relevant chunks rather than the specific clause.

**How to detect it:** the agent's answer is vague or mixes concepts from different topics. The tool was called but the query was not specific enough.

**Fix:** add explicit instructions in the agent prompt: "When searching for IS code content, always include the IS code number in your search query."

---

### Failure Mode 2 — Infinite Loop

The agent keeps calling tools without deciding the task is complete.

**Example:** the agent searches IS 456, finds a reference to IS 1893, searches IS 1893, finds a reference to IS 800, searches IS 800, finds a reference to IS 2062 — and keeps following references without stopping.

**How to detect it:** the workflow runs for an unusually long time. n8n shows the agent making many tool calls in sequence.

**Fix:** n8n's AI Agent node has a **Max Iterations** setting. Set this to 5-8 for domain reference tasks — enough to follow one or two cross-references but not enough to loop indefinitely.

---

### Failure Mode 3 — Hallucinated Tool Calls

The agent invents a tool call result rather than actually calling the tool.

**Example:** the agent decides to search Pinecone for IS 456 Clause 26.4 but instead of actually retrieving the chunk, it generates what it thinks the clause says from its training data — and presents this as if it came from the search.

**How to detect it:** the agent's cited sources do not match what is in Pinecone when you check manually. The answer may be generally correct but the citation does not verify.

**Fix:** this is the hardest failure mode to catch. For high-stakes domain use, always verify at least one citation from the agent's output by manually searching Pinecone for the same query.

---

### Failure Mode 4 — Scope Creep

The agent goes beyond what was asked, using tools and retrieving information the task did not require.

**Example:** a civil engineer asks "what is the minimum column dimension per IS 456?" The agent answers the question but also retrieves earthquake zone information, foundation depth requirements, and material specifications — none of which were asked for. The answer is technically correct but far larger than needed and harder to verify.

**How to detect it:** the agent's output covers many more topics than the question asked about. The answer is long and the engineer cannot quickly find the specific value they needed.

**Fix:** add a constraint to the agent prompt: "Answer only the specific question asked. Do not retrieve additional information beyond what is directly relevant to the question."

---

## The Four Failure Modes — At a Glance

| Failure mode | What happens | How to detect | Fix |
|---|---|---|---|
| **Tool misuse** | Tool called with wrong query | Answer is vague or mixes topics | Add specific query instructions to prompt |
| **Infinite loop** | Agent keeps calling tools | Workflow runs too long | Set Max Iterations to 5-8 |
| **Hallucinated tool call** | Agent invents tool result | Citations do not verify in Pinecone | Manually verify one citation |
| **Scope creep** | Agent retrieves too much | Answer covers more than was asked | Add "answer only what was asked" constraint |

## Best Practices

- Always set Max Iterations on the AI Agent node — without a limit, the agent can run indefinitely
- Start with one tool (Pinecone only) and add tools one at a time — adding all tools at once makes it harder to identify which tool is causing a failure
- Keep the agent prompt explicit about what to search for — vague prompts produce vague tool calls
- For high-stakes domain decisions, always verify at least one citation manually — hallucinated tool calls are hard to detect from the output alone
- Disable the web search tool for exam prep and IS code reference tasks — it returns general information that may conflict with course-specific content

## Common Beginner Mistakes

- **Giving the agent too many tools** — more tools means more ways the agent can go wrong. Add only the tools the task actually needs
- **Not setting Max Iterations** — a loop that runs 50 iterations before timing out is expensive and produces no useful output
- **Trusting the agent's citations without verification** — hallucinated tool calls are the hardest failure mode to detect because the output looks cited and authoritative
- **Using an agent when a fixed pipeline would do** — if the task always follows the same steps, a fixed pipeline is safer, faster, and easier to audit

---

## Key Takeaways

- A tool-using agent decides what to do next based on what it finds — unlike a fixed pipeline which follows the same sequence every time
- The four tools available in n8n: Vector Store Query (Pinecone), Document Reader, Calculator, Web Search
- The four agent failure modes: Tool Misuse, Infinite Loop, Hallucinated Tool Calls, Scope Creep
- Always set Max Iterations to prevent infinite loops
- For high-stakes professional domains, fixed pipelines with human checkpoints are safer than autonomous agents
- The next topic compares both builds side by side to help decide when to use each

> **Interview tip:** If asked "what are the risks of using AI agents?" — name all four failure modes with one specific example for each. Most candidates say "the agent might give wrong answers." Naming tool misuse, infinite loops, hallucinated tool calls, and scope creep as distinct failure modes — each with a different cause and a different fix — shows you understand agents as engineering systems with specific, diagnosable failure patterns.
