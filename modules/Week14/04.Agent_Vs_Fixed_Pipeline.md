# Agent vs Fixed Pipeline — When to Use Each

- Explain why fixed pipelines are safer for high-stakes professional domains
- Identify the trust calibration problem as it applies to agents

## Overview

The previous two topics built both systems in n8n:

- A **fixed pipeline** — Manual Trigger → Pinecone → Claude — that always runs the same three steps in the same order
- A **tool-using agent** — AI Agent with Anthropic Chat Model and Pinecone as a tool — that decides what to do next based on what it finds

Now that you have built both, the comparison is between two things you have seen working — not two abstract concepts. This topic puts them side by side and provides a decision framework for choosing between them.

---

## Side-by-Side Comparison

```text
FIXED PIPELINE                          TOOL-USING AGENT
──────────────────────────────────────────────────────────────
Steps defined before running            Steps decided during running
Same path every time                    Path changes based on findings
Auditable — every step inspectable      Less auditable — decisions internal
Fast — no decision overhead             Slower — decision at each step
Predictable output for same input       Output may vary for same input
Safe for high-stakes domains            Riskier for high-stakes domains
Better for known, repeatable tasks      Better for exploratory tasks
Easy to test with golden dataset        Harder to test systematically
Human checkpoint easy to place          Human checkpoint harder to define
```

## What the Builds Showed

### From the Fixed Pipeline Build

When you ran the fixed pipeline with "What is the minimum clear cover for a column in moderate exposure?" — the path was always the same:

```text
Question → Pinecone (retrieves top 4 chunks) → Claude (generates answer)
```

Every time. For every question. The same three nodes in the same order. You knew exactly what would happen before you clicked Execute workflow.

**What this gives you:** predictability. The HITL checkpoint is obvious — it sits between Claude and any action the engineer takes on the output. The golden dataset tests exactly the path the pipeline takes. If a question fails, you know which node to investigate.

### From the Agent Build

When you ran the agent with "What IS codes apply to a reinforced concrete column in seismic zone III?" — the agent:

1. Received the question
2. Decided to search Pinecone — formulating its own query: **"IS codes for reinforced concrete column design seismic zone III"**
3. Got a tool error from Pinecone
4. Decided to answer from general knowledge instead — explaining what it was doing and why
5. Produced a 2,616-token output explaining its reasoning

The path was not defined in advance. The agent made four separate decisions. The output was not just an answer — it was a narrative of the agent's reasoning process.

**What this gives you:** flexibility. The agent adapted when its tool failed. It explained its reasoning. It produced a more complete response. But you also had less control — the agent decided what to search for, not you.

## The Decision Framework

Use this framework to choose between a fixed pipeline and an agent for any professional task:

```text
QUESTION 1 — Are the steps known in advance?

YES → Fixed pipeline is appropriate
NO  → Agent may be needed — continue to Question 2

QUESTION 2 — Are the steps auditable?
(Can a human inspect every step the system took?)

MUST BE AUDITABLE → Fixed pipeline is required
AUDITABILITY FLEXIBLE → Agent may be appropriate — continue to Question 3

QUESTION 3 — Are the stakes high if the system makes a wrong decision?

HIGH STAKES → Fixed pipeline with human checkpoints
LOW STAKES → Agent with monitoring is acceptable

QUESTION 4 — Is the task exploratory or repeatable?

REPEATABLE (same task done many times) → Fixed pipeline
EXPLORATORY (task changes based on what is found) → Agent
```

**For the civil engineering knowledge assistant:**

| Question | Answer | Implication |
|---|---|---|
| Are the steps known in advance? | Yes — retrieve IS code clause, generate cited answer | Fixed pipeline |
| Must be auditable? | Yes — structural design decisions must be traceable | Fixed pipeline required |
| High stakes? | Yes — wrong IS code value could affect structural safety | Fixed pipeline with Model 1 HITL |
| Repeatable or exploratory? | Repeatable — same pattern for every question | Fixed pipeline |

**Verdict: fixed pipeline for the civil engineering IS code assistant.** Every criterion points the same way.

## When an Agent Is the Right Choice

The civil engineering case is clear. But there are professional scenarios where an agent is genuinely the better choice:

**Scenario 1 — Project brief analysis**
A civil engineer uploads a 50-page project specification. The task is: identify all structural requirements, find the relevant IS codes for each, flag any conflicts between requirements, and produce a compliance summary.

The steps are not known in advance — the engineer does not know how many requirements are in the brief, which IS codes apply, or whether there are conflicts. The task is exploratory. An agent that reads the brief, decides what to look up, looks it up, finds conflicts, and produces a summary is appropriate here.

**Human oversight still required:** the engineer reviews the compliance summary before it is acted on. The agent does the research — the engineer makes the decision.

**Scenario 2 — Research assistant for a new topic**
A student is starting to revise a topic they have not studied before. They want to understand the connections between concepts — not just answers to specific questions. An agent can follow the thread: "explain X → that connects to Y → find more about Y → that references Z → explain Z." A fixed pipeline would require the student to know what to ask for each step.

**Human oversight:** the student reads the agent's output critically, knowing it may have followed a thread that diverged from what the notes actually cover.

## The Trust Calibration Problem for Agents

The trust calibration problem introduced in the Human-in-the-Loop Design topic is harder for agents than for fixed pipelines.

**For a fixed pipeline:**
You run the golden dataset — 10 questions, 4 types — before and after any changes. The same path runs every time. If 8 out of 10 pass, you have a meaningful reliability score. You know the pipeline is 80% reliable on direct concept questions.

**For an agent:**
The same question can produce a different path on different runs. The agent might search Pinecone differently, formulate different queries, follow different references. The output varies even when the input is identical. Your golden dataset gives you a distribution of results — not a single reliability score. And the failure modes are harder to diagnose because the path is not fixed.

**What this means in practice:**
- Test agents with many more inputs than fixed pipelines — a golden dataset of 10 questions is not enough
- Watch for the agent's reasoning, not just its output — the reasoning tells you whether the agent is using its tools correctly
- Set Max Iterations before deploying — an agent without an iteration limit can run indefinitely on a complex task

## The Practical Rule

For every professional domain covered in this course — civil engineering, mechanical, pharma, CS, data science — the practical rule is:

```text
USE A FIXED PIPELINE FOR:
- Answering specific questions from a known knowledge base
- Tasks that follow the same steps every time
- Decisions that must be auditable and verified
- High-stakes professional domains

USE AN AGENT FOR:
- Research tasks where the steps depend on what is found
- Exploratory analysis of complex documents
- Tasks where the path cannot be defined in advance
- Lower-stakes tasks where flexibility matters more than predictability
```

The exam prep chatbot, the civil engineering IS code assistant, the domain application built in Week 13 — all of these are fixed pipeline applications. The steps are known. The task is repeatable. The stakes are identifiable. The HITL checkpoint is clear.

An agent version of any of these would be appropriate only for specific exploratory tasks — not for the core reference and answer use case.

## Best Practices

- Default to a fixed pipeline — only choose an agent when a specific requirement cannot be met by a fixed pipeline
- Document the reason for choosing an agent — if you cannot explain why a fixed pipeline would not work, reconsider the choice
- Always set Max Iterations on any agent you deploy — treat it as a non-negotiable safety setting
- Test agents with more inputs than fixed pipelines — the variable path means a small test set does not give a reliable picture
- For high-stakes professional domains — if in doubt, choose the fixed pipeline

## Common Beginner Mistakes

- **Choosing an agent because it feels more advanced** — an agent is not an upgraded pipeline. It is a different tool for a different kind of task. Using an agent for a repeatable retrieval task adds complexity and risk without adding value
- **Not placing a HITL checkpoint for agents** — agents are harder to audit than pipelines, which makes human review more important, not less
- **Treating agent output as more reliable than pipeline output** — agents use more tokens, reason through more steps, and produce longer outputs — none of which makes them more accurate. Accuracy depends on the tools and data, not on the complexity of the reasoning

---

## Key Takeaways

- A fixed pipeline always runs the same steps in the same order — predictable, auditable, testable with a golden dataset
- An agent decides what steps to take based on what it finds — flexible, exploratory, harder to audit
- The decision framework: use a fixed pipeline when steps are known, auditability is required, stakes are high, or the task is repeatable; use an agent when steps are unknown and the task is exploratory
- For the civil engineering IS code assistant — and all domain reference applications in this course — a fixed pipeline is the right choice
- The trust calibration problem is harder for agents because the same question can produce a different path on different runs
- Always set Max Iterations on any deployed agent — treat it as a safety requirement, not an optional setting

> **Interview tip:** If asked "would you use a pipeline or an agent for this task?" — apply the four-question decision framework out loud: are the steps known, must it be auditable, how high are the stakes, is it repeatable or exploratory? Name which way each answer points. Then give your verdict with one sentence of justification. Most candidates say "it depends" without explaining what it depends on. Walking through the four questions shows you can make the decision systematically rather than by instinct.
