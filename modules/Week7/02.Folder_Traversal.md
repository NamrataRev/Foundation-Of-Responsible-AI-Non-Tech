# Folder Traversal

## The Problem This Solves

In any automation pipeline, the first job is always the same — find the files. Before pandas can read a CSV, before openpyxl can open an Excel file, before pdfplumber can extract a table from a PDF, something has to navigate the folder, identify what is there, and hand each file to the right tool. That is the entry point of the Python Automation Toolkit, and it is what this file covers.

Imagine the university's exam office has a folder called `results/` on their computer. Every semester, each department drops their student result files into it. By the end of the semester the folder looks like this:

```text
results/
├── cs_results.csv
├── management_results.xlsx
├── external_board_results.pdf
├── notes.txt
└── archive/
    ├── cs_results_jan.csv
    └── mgmt_results_jan.xlsx
```

A staff member needs to process all the result files — read the marks, combine them, calculate grades, and produce a final report. Doing this manually — opening each file one by one — takes hours and is prone to mistakes. Worse, next semester the folder will have different file names.

The goal is a Python program that opens the folder, finds all the relevant files automatically, identifies what type each one is, and passes each to the right reader — without the staff member doing anything except running the script.

That is what folder traversal is: writing code that navigates a folder structure the same way you would with a file explorer, but automatically and at any scale.

## The Two Tools

Python provides two built-in modules for working with files and folders.

| Module | Style | Introduced |
|---|---|---|
| `os` | Functions — `os.listdir()`, `os.path.join()` | Original, available everywhere |
| `pathlib` | Object-oriented — `Path("folder").iterdir()` | Python 3.4+, more readable |

Both are built into Python — no installation needed. `pathlib` is the modern approach and the one this file focuses on, with `os` shown where it is still commonly used. You will see both in real code.

## Absolute vs Relative Paths

Before writing any code that opens a file or folder, you need to understand one fundamental concept — where is Python looking?

**A relative path** is written without a drive letter or root. It is resolved from wherever Python is currently running — called the **current working directory**.

```python
Path("results")           # looks for results/ in the current working directory
Path("results/cs_results.csv")   # looks inside that folder
```

Think of it like giving someone directions from where they are standing right now. "Turn left, then second right" only works if you both know the starting point.

**An absolute path** gives the complete location from the top of the drive — it works no matter where Python is running from.

```python
Path("C:/Users/Alex/project/results")       # Windows
Path("/home/alex/project/results")           # Mac / Linux
```

**Why this matters in the pipeline:**
If the script is run from inside the `project/` folder, `Path("results")` finds the folder correctly. If it is run from the desktop or any other folder, Python looks for `results/` there — and raises a `FileNotFoundError` because it does not exist.

The safest approach for any automation script is to build the path relative to the script file itself, not relative to wherever Python happens to be running:

```python
from pathlib import Path

# __file__ is the path to the current script
# .parent gives the folder the script is in
# / "results" adds the results subfolder to that path
BASE_DIR = Path(__file__).parent
results_folder = BASE_DIR / "results"

print(results_folder)
```

**Output**

```text
/home/alex/project/results
```

Now the script finds `results/` correctly no matter where it is launched from. Use this pattern in every automation script.

## The `pathlib` Module

### The Path Object

`pathlib` works around one idea: instead of treating a file location as a plain string, wrap it in a `Path` object that knows what it represents and what you can do with it.

```python
from pathlib import Path

p = Path("results")
print(p)
print(type(p))
```

**Output**

```text
results
<class 'pathlib.PosixPath'>
```

The `Path` object looks like a string when printed but behaves like an object — it has methods and properties that make file work much cleaner than string manipulation.

### Checking Whether a Path Exists

Before trying to open or list a folder, check that it is there.

```python
from pathlib import Path

folder = Path("results")

if folder.exists():
    print("Folder found")
else:
    print("Folder not found — check the path")
```

**Output**

```text
Folder found
```

Two related checks tell you what kind of path it is:

```python
print(folder.is_dir())    # True if it is a folder
print(folder.is_file())   # True if it is a file
```

**Output**

```text
True
False
```

### Creating a Folder

If the `results/processed/` folder does not exist yet and you need to write output files into it, create it first.

```python
from pathlib import Path

output = Path("results/processed")
output.mkdir(parents=True, exist_ok=True)
print("Output folder ready")
```

**Output**

```text
Output folder ready
```

`parents=True` creates any missing parent folders — `results/` will be created first if it does not exist. `exist_ok=True` stops Python from raising an error if the folder already exists. Use both together as a safe default.

### Listing the Contents of a Folder

`iterdir()` returns every item inside a folder — files and subfolders both — one at a time.

```python
from pathlib import Path

folder = Path("results")

for item in folder.iterdir():
    print(item)
```

**Output**

```text
results/cs_results.csv
results/management_results.xlsx
results/external_board_results.pdf
results/notes.txt
results/archive
```

Each `item` is itself a `Path` object, so you can immediately call `.is_file()`, `.suffix`, or any other method on it.

### Useful Path Properties

Once you have a `Path` object, several properties pull out the parts you need without any string splitting.

```python
from pathlib import Path

p = Path("results/cs_results.csv")

print(p.name)        # cs_results.csv     — file name with extension
print(p.stem)        # cs_results          — file name without extension
print(p.suffix)      # .csv               — extension including the dot
print(p.parent)      # results             — the containing folder
```

**Output**

```text
cs_results.csv
cs_results
.csv
results
```

These properties mean you never need to split a filename string manually. Checking `p.suffix == ".csv"` is all it takes to know whether a file is a CSV.

### Reading and Writing Files Directly — read_text() and write_text()

`pathlib` can read and write plain text files directly without using `open()`. This is useful for quick reads inside the pipeline — for example, checking a config file or writing a log:

```python
from pathlib import Path

# write a log entry
log = Path("results/pipeline_log.txt")
log.write_text("Pipeline started. Files found: 3.")

# read it back
content = log.read_text()
print(content)
```

**Output**

```text
Pipeline started. Files found: 3.
```

`write_text()` creates the file if it does not exist and overwrites it if it does. `read_text()` reads the entire file as one string. For structured data — CSV, Excel, PDF — always use the dedicated tool (pandas, openpyxl, pdfplumber). These two methods are for simple plain text only.

### Filtering Files by Extension — glob()

`glob()` lists only the items that match a pattern. `"*.csv"` means "any name, ending in `.csv`".

```python
from pathlib import Path

folder = Path("results")

for file in folder.glob("*.csv"):
    print(file.name)
```

**Output**

```text
cs_results.csv
```

The `*` is a wildcard that matches any sequence of characters. Other useful patterns:

| Pattern | Matches |
|---|---|
| `"*.csv"` | Every CSV in this folder |
| `"*.xlsx"` | Every Excel file in this folder |
| `"**/*.csv"` | Every CSV in this folder and all subfolders |
| `"cs_*"` | Every file whose name starts with `cs_` |

The double-star `**` is the key to recursive search — it descends into every subfolder automatically.

### Recursive Search — rglob()

`rglob("*.csv")` is shorthand for `glob("**/*.csv")` — it finds every matching file in the folder and every subfolder inside it, no matter how deeply nested.

```python
from pathlib import Path

folder = Path("results")

for file in folder.rglob("*.csv"):
    print(file)
```

**Output**

```text
results/cs_results.csv
results/archive/cs_results_jan.csv
```

Both the top-level CSV and the one inside `archive/` are found automatically.

## The `os` Module

`os` is the older approach. You will encounter it constantly in existing code, so it is worth knowing the most common functions.

### os.getcwd() and os.listdir()

```python
import os

print(os.getcwd())          # prints the current working directory
print(os.listdir("results")) # lists everything in the results folder
```

**Output**

```text
/home/user/project
['cs_results.csv', 'management_results.xlsx', 'external_board_results.pdf', 'notes.txt', 'archive']
```

`os.listdir()` returns plain strings, not `Path` objects. To check whether an item is a file or folder, you have to join the path yourself first.

The `os` equivalents of pathlib's `.exists()`, `.is_file()`, and `.is_dir()` are:

```python
import os

print(os.path.exists("results"))           # True if the path exists at all
print(os.path.isfile("results/cs_results.csv"))   # True if it is a file
print(os.path.isdir("results"))            # True if it is a folder
```

**Output**

```text
True
True
True
```

You will see these three functions constantly in existing Python automation code. They do exactly what the pathlib equivalents do — the syntax is just different.

### os.path.join() — Building Paths Safely

Never build a file path by concatenating strings with `+` or `/`. Different operating systems use different separators — `\` on Windows, `/` on Mac and Linux. `os.path.join()` picks the right one automatically.

```python
import os

folder = "results"
filename = "cs_results.csv"

path = os.path.join(folder, filename)
print(path)
```

**Output**

```text
results/cs_results.csv
```

With `pathlib`, the `/` operator does the same job more cleanly:

```python
from pathlib import Path

path = Path("results") / "cs_results.csv"
print(path)
```

**Output**

```text
results/cs_results.csv
```

### os.walk() — Walking an Entire Tree

`os.walk()` visits every folder and subfolder in a tree, giving you the folder path, its subfolders, and its files on each step.

```python
import os

for root, dirs, files in os.walk("results"):
    print("In folder:", root)
    for filename in files:
        print("  File:", filename)
```

**Output**

```text
In folder: results
  File: cs_results.csv
  File: management_results.xlsx
  File: external_board_results.pdf
  File: notes.txt
In folder: results/archive
  File: cs_results_jan.csv
  File: mgmt_results_jan.xlsx
```

`root` is the current folder as a string, `dirs` is a list of subfolder names inside it, and `files` is a list of file names inside it. To build the full path to a file, join them:

```python
import os

for root, dirs, files in os.walk("results"):
    for filename in files:
        full_path = os.path.join(root, filename)
        print(full_path)
```

**Output**

```text
results/cs_results.csv
results/management_results.xlsx
results/external_board_results.pdf
results/notes.txt
results/archive/cs_results_jan.csv
results/archive/mgmt_results_jan.xlsx
```

## The `shutil` Module — Copying and Moving Files

`shutil` handles operations that `os` and `pathlib` do not — copying and moving files and entire folders. It is part of the standard library, so no installation is needed.

In the pipeline, once a file has been processed, it is copied to the `results/processed/` folder so the original is never touched.

**Copying a single file:**

```python
import shutil

shutil.copy("results/cs_results.csv", "results/processed/cs_results.csv")
print("File copied")
```

**Output**

```text
File copied
```

**Moving a file** — removes it from the original location:

```python
import shutil

shutil.move("results/cs_results.csv", "results/processed/cs_results.csv")
print("File moved")
```

**Output**

```text
File moved
```

**Copying an entire folder** including all its contents:

```python
import shutil

shutil.copytree("results/archive", "results/archive_backup")
print("Folder copied")
```

**Output**

```text
Folder copied
```

**Deleting an entire folder** — removes the folder and everything inside it permanently:

```python
import shutil

shutil.rmtree("results/archive_backup")
print("Folder deleted")
```

**Output**

```text
Folder deleted
```

`shutil.rmtree()` has no undo. Once called, every file inside the folder is gone. Always verify the path is exactly right before calling it — print it first if there is any doubt.

## Applying It to the Results Folder

Here is the complete folder traversal step for the student result processing pipeline. The script opens the `results/` folder, identifies every file, and prints what kind of reader each one needs.

Notice the `results/` folder also contains an `archive/` subfolder with past semester files. The routing script should only process current files — not old ones. The check `"archive" not in file.parts` skips any file that lives inside the archive subfolder.

```python
from pathlib import Path

READERS = {
    ".csv":  "pandas",
    ".xlsx": "openpyxl",
    ".pdf":  "pdfplumber",
}

BASE_DIR = Path(__file__).parent
results_folder = BASE_DIR / "results"

if not results_folder.exists():
    print("results/ folder not found")
else:
    for file in results_folder.iterdir():
        if file.is_file() and "archive" not in file.parts:
            # file.parts breaks the path into its components
            # e.g. ("results", "archive", "cs_results_jan.csv")
            # checking "archive" not in file.parts skips archived files
            reader = READERS.get(file.suffix)
            if reader:
                print(f"{file.name}  →  read with {reader}")
            else:
                print(f"{file.name}  →  skipped (unsupported type)")
```

**Output**

```text
cs_results.csv          →  read with pandas
management_results.xlsx →  read with openpyxl
external_board_results.pdf →  read with pdfplumber
notes.txt               →  skipped (unsupported type)
```

The archive files — `cs_results_jan.csv` and `mgmt_results_jan.xlsx` — are silently skipped because they live inside the `archive/` subfolder.

This is the entry point of the full Python Automation Toolkit pipeline. The routing script produces a file path for each result file — in the next topic, pandas takes the `.csv` path and reads it into a DataFrame. The routing script itself does not change as the pipeline grows — only the handlers for each file type are added.

## Common Mistakes

- Building paths with string concatenation like `"results/" + filename` — breaks on Windows. Use `Path("results") / filename` or `os.path.join()`.
- Calling `iterdir()` on a path that does not exist — raises a `FileNotFoundError`. Always check `.exists()` first.
- Forgetting that `os.listdir()` returns strings, not full paths — joining with the parent folder is needed before you can open or check the file.
- Using `glob("*.csv")` when you also need files in subfolders — use `rglob("*.csv")` instead.
- Deleting with `shutil.rmtree()` without checking the path — it permanently removes everything inside. Always verify the path is correct before calling it.
- Confusing `p.name` (filename with extension) and `p.stem` (filename without extension).
