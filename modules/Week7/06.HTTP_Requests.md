# HTTP Requests

## The Problem This Solves

The three departments have been processed. The combined DataFrame now has 11 students across CS, Management, and External Board — all with marks out of 100. Every tool in the Python Automation Toolkit so far has worked with local files. This final tool is different — `requests` is the toolkit's connection to the outside world. It fetches live data from APIs over the internet and brings it into the pipeline. Without it, the automation is limited to what already exists on the local machine. With it, the pipeline can pull in live exchange rates, current benchmarks, AI model responses, or any other data that lives on a remote server.

The head of department wants one more column: each student's marks compared against the national average, fetched live from the university's grading API.

**Quick glossary:**

| Term | Meaning |
|---|---|
| **HTTP** | HyperText Transfer Protocol — the language computers use to communicate over the web |
| **API** | Application Programming Interface — a service that lets your program ask for data or perform actions over the internet |
| **Request** | Your program asking a server for something |
| **Response** | The server's reply — contains a status code and usually some data |
| **Status code** | A number that says whether the request succeeded (200), failed (404), or had a server error (500) |
| **Endpoint** | One specific URL an API exposes for one specific purpose |
| **JSON response** | Most APIs send their data back as JSON — which you already know how to parse |

## How HTTP Works — The Simple Version

Every time you open a webpage, your browser sends a **request** to a server. The server sends back a **response**. Your browser renders the response as a page you can read.

Your Python program does the same thing — but instead of rendering a page, it reads the data from the response and uses it in code.

```text
Your Python program                      Server (API)
        │                                     │
        │  GET https://api.example.com/marks  │
        │ ──────────────────────────────────► │
        │                                     │
        │  200 OK                             │
        │  {"national_average": 72.4}         │
        │ ◄────────────────────────────────── │
        │                                     │
```

## HTTP Methods — The Four Verbs

Every request uses a method that says what kind of action you are taking:

| Method | What it does | When you use it |
|---|---|---|
| **GET** | Ask for data | Fetching results, exchange rates, weather |
| **POST** | Send new data to create something | Submitting a form, calling an AI model |
| **PUT** | Send data to update something existing | Updating a student record |
| **DELETE** | Remove something | Deleting a record |

In the student results pipeline, you will use **GET** to fetch the national average from the API and **POST** to send a student's marks to the grading service for a benchmark comparison. Most APIs you will encounter in AI work use GET and POST.

## Making a GET Request

`requests.get()` sends a GET request to a URL and returns a response object:

```python
import requests

response = requests.get("https://api.example.com/grading/national-average")
print(response.status_code)
print(response.text)
```

**Output**

```text
200
{"subject": "all", "national_average": 72.4, "year": 2026}
```

`200` means success. `response.text` is the raw response body as a string.

### Understanding Status Codes

| Code | Meaning | What to do |
|---|---|---|
| `200` | OK — success | Use the response |
| `201` | Created — POST succeeded | Use the response |
| `400` | Bad Request — your request had an error | Check your parameters |
| `401` | Unauthorised — API key missing or wrong | Check your credentials |
| `403` | Forbidden — you do not have permission | Check your account |
| `404` | Not Found — the endpoint does not exist | Check the URL |
| `429` | Too Many Requests — rate limited | Wait before retrying |
| `500` | Server Error — problem on the API's end | Try again later |

```python
if response.status_code == 200:
    print("Success")
elif response.status_code == 404:
    print("Endpoint not found — check the URL")
else:
    print(f"Unexpected status: {response.status_code}")
```

### Parsing a JSON Response

Most APIs return JSON. `response.json()` parses it directly into a Python dictionary — no need to call `json.loads()` separately:

```python
import requests

response = requests.get("https://api.example.com/grading/national-average")
data = response.json()

print(data["national_average"])
print(type(data))
```

**Output**

```text
72.4
<class 'dict'>
```

`data` is now an ordinary Python dictionary. You can read values from it, pass it to pandas, or store it in a variable — exactly like any other dictionary.

## Query Parameters

Query parameters let you filter or customise what the API returns. You pass them as a dictionary to the `params` argument — `requests` builds the URL automatically:

```python
import requests

params = {
    "subject": "Mathematics",
    "year": 2026
}

response = requests.get(
    "https://api.example.com/grading/national-average",
    params=params
)

print(response.url)
print(response.json())
```

**Output**

```text
https://api.example.com/grading/national-average?subject=Mathematics&year=2026
{"subject": "Mathematics", "national_average": 74.1, "year": 2026}
```

Never build the URL by concatenating strings — `requests` handles encoding special characters automatically. `response.url` shows you the exact URL that was sent.

## Headers — Sending an API Key

Most real APIs require authentication. You prove who you are by including an API key in the request headers.

```python
import requests

headers = {
    "Authorization": "Bearer YOUR_API_KEY_HERE",
    "Content-Type": "application/json"
}

response = requests.get(
    "https://api.example.com/grading/national-average",
    headers=headers
)

print(response.status_code)
```

**Output**

```text
200
```

The API key goes in the `Authorization` header. The exact format (`Bearer`, `Token`, `ApiKey`) depends on the specific API — always check the documentation.

**Never hardcode an API key directly in your script.** Store it in an environment variable or a separate config file that is not shared:

```python
import os
import requests

api_key = os.environ.get("GRADING_API_KEY")

headers = {"Authorization": f"Bearer {api_key}"}
response = requests.get("https://api.example.com/grading/national-average",
                        headers=headers)
```

## Making a POST Request

A POST request sends data to the server — typically to create something or trigger a calculation. The data goes in the `json` argument:

```python
import requests

student_data = {
    "student_id": "S001",
    "subject": "Mathematics",
    "marks": 78,
    "max_marks": 100
}

response = requests.post(
    "https://api.example.com/grading/benchmark",
    json=student_data,
    headers={"Authorization": "Bearer YOUR_API_KEY_HERE"}
)

result = response.json()
print(result)
```

**Output**

```text
{"student_id": "S001", "marks": 78, "percentile": 64.2, "band": "Above Average"}
```

`json=student_data` tells `requests` to convert the dictionary to JSON and set the `Content-Type` header automatically. You do not need to call `json.dumps()` yourself.

## Session — Reusing a Connection

Every time you call `requests.get()` or `requests.post()`, Python opens a new connection to the server and closes it when the response arrives. If you are calling the same API 11 times — once per student — that is 11 separate connections, each carrying the same headers.

A `Session` object keeps the connection open and remembers the headers, so you set them once and every subsequent call uses them automatically:

```python
import requests

session = requests.Session()
session.headers.update({
    "Authorization": "Bearer YOUR_API_KEY_HERE",
    "Content-Type": "application/json"
})

r1 = session.get("https://api.example.com/grading/national-average",
                 params={"subject": "Mathematics"})
r2 = session.get("https://api.example.com/grading/national-average",
                 params={"subject": "Finance"})

print(r1.json()["national_average"])
print(r2.json()["national_average"])

session.close()
```

**Output**

```text
74.1
69.8
```

Or use it as a context manager so it closes automatically:

```python
with requests.Session() as session:
    session.headers.update({"Authorization": "Bearer YOUR_API_KEY_HERE"})
    for subject in ["Mathematics", "Finance", "Data Science"]:
        r = session.get("https://api.example.com/grading/national-average",
                       params={"subject": subject}, timeout=5)
        r.raise_for_status()
        print(subject, r.json()["national_average"])
```

**Output**

```text
Mathematics 74.1
Finance 69.8
Data Science 71.3
```

Use a `Session` whenever you are making multiple calls to the same API in a loop — it is faster and cleaner than repeating the headers dictionary on every call.

## Error Handling

Network calls can fail — the server might be down, your internet might drop, or the API might return an error status. Always wrap requests in error handling.

### raise_for_status()

`raise_for_status()` raises an exception automatically if the status code indicates failure (4xx or 5xx). This is cleaner than checking the status code manually for every call:

```python
import requests

response = requests.get("https://api.example.com/grading/national-average")

try:
    response.raise_for_status()
    data = response.json()
    print(data["national_average"])
except requests.exceptions.HTTPError as e:
    print(f"HTTP error: {e}")
```

**Output** (when the API returns 401):

```text
HTTP error: 401 Client Error: Unauthorized for url: https://api.example.com/...
```

### Handling Connection Failures

`raise_for_status()` only handles HTTP errors — a response that arrived but had a bad status code. A network failure (no internet, server unreachable) raises a different exception:

```python
import requests

try:
    response = requests.get(
        "https://api.example.com/grading/national-average",
        timeout=5
    )
    response.raise_for_status()
    data = response.json()
    print(data["national_average"])
except requests.exceptions.ConnectionError:
    print("No internet connection or server unreachable")
except requests.exceptions.Timeout:
    print("Request timed out — server took too long to respond")
except requests.exceptions.HTTPError as e:
    print(f"HTTP error: {e}")
```

`timeout=5` means: if the server has not responded within 5 seconds, stop waiting and raise a `Timeout` exception. Without a timeout, your program can hang forever waiting for a response that never comes. Always set a timeout in production code.

## Applying It to the Pipeline

The combined DataFrame has all 11 students. Now fetch the national average per subject and add it as a new column:

```python
import requests
import pandas as pd

def fetch_national_average(subject):
    try:
        response = requests.get(
            "https://api.example.com/grading/national-average",
            params={"subject": subject},
            timeout=5
        )
        response.raise_for_status()
        return response.json()["national_average"]
    except requests.exceptions.RequestException as e:
        print(f"Could not fetch average for {subject}: {e}")
        return None

combined_df = pd.read_csv("results/processed/combined_results.csv")

combined_df["national_average"] = combined_df["subject"].apply(
    fetch_national_average
)

combined_df["above_national_avg"] = (
    combined_df["marks"] > combined_df["national_average"]
)

print(combined_df[["name", "subject", "marks", "national_average", "above_national_avg"]])
```

**Output**

```text

0    Alex   Mathematics     78              74.1                True
1   Maria   Mathematics     92              74.1                True
2   James   Mathematics     55              74.1               False
3     Sam   Mathematics      0              74.1               False
4  Jordan   Mathematics     88              74.1                True
```

## The Complete Pipeline — Putting It All Together

All five files now connect into one working automation:

```python
from pathlib import Path
import pandas as pd
import openpyxl
import pdfplumber
import requests
from openpyxl.styles import Font, PatternFill
from openpyxl.utils.dataframe import dataframe_to_rows

# ── Step 1: Traverse the folder ──────────────────────────────────────
results_folder = Path("results")
dfs = []

for file in results_folder.iterdir():
    if not file.is_file():
        continue

    # ── Step 2: Read each file type ──────────────────────────────────
    if file.suffix == ".csv":
        df = pd.read_csv(file)
        dfs.append(df)

    elif file.suffix == ".xlsx":
        df = pd.read_excel(file, skiprows=2)
        dfs.append(df)

    elif file.suffix == ".pdf":
        with pdfplumber.open(file) as pdf:
            table = pdf.pages[0].extract_table()
        if table:
            header  = table[0]
            records = table[1:]
            df = pd.DataFrame(records, columns=header)
            df["marks"]     = pd.to_numeric(df["marks"])
            df["max_marks"] = pd.to_numeric(df["max_marks"])
            dfs.append(df)

# ── Step 3: Combine all DataFrames ───────────────────────────────────
combined = pd.concat(dfs, ignore_index=True)
combined["marks"] = combined["marks"].fillna(0)
combined["percentage"] = (combined["marks"] / combined["max_marks"]) * 100

# ── Step 4: Fetch national averages from API ─────────────────────────
def fetch_average(subject):
    try:
        r = requests.get(
            "https://api.example.com/grading/national-average",
            params={"subject": subject},
            timeout=5
        )
        r.raise_for_status()
        return r.json()["national_average"]
    except requests.exceptions.RequestException:
        return None

combined["national_average"] = combined["subject"].apply(fetch_average)
combined["above_avg"] = combined["marks"] > combined["national_average"]

# ── Step 5: Write formatted Excel report ─────────────────────────────
Path("results/processed").mkdir(exist_ok=True)

wb = openpyxl.Workbook()
ws = wb.active
ws.title = "Combined Results"

for row in dataframe_to_rows(combined, index=False, header=True):
    ws.append(row)

for cell in ws[1]:
    cell.font = Font(bold=True)

red_fill = PatternFill(fill_type="solid", fgColor="FFCCCC")
for row in ws.iter_rows(min_row=2):
    pct_cell = row[5]
    if pct_cell.value is not None and float(pct_cell.value) < 40:
        for cell in row:
            cell.fill = red_fill

wb.save("results/processed/final_report.xlsx")
print("Pipeline complete — final_report.xlsx saved")
```

**Output**

```text
Pipeline complete — final_report.xlsx saved
```

The five files together — folder traversal, pandas, openpyxl, pdfplumber, requests — form a complete, working automation. A staff member drops result files into the `results/` folder, runs one script, and gets a formatted Excel report with grades, percentages, and national average comparisons.

## Common Mistakes

- Not setting `timeout` — without it, a slow or unresponsive server hangs your program indefinitely.
- Not calling `raise_for_status()` — a 404 or 500 response is not an exception by default; your program will try to parse the error message as data and fail in a confusing way.
- Hardcoding API keys in the script — use `os.environ.get()` or a config file that is excluded from version control.
- Building the URL manually with string concatenation — use `params={}` and let `requests` handle encoding.
- Calling the API once per row in a large DataFrame without caching — if 1,000 students all study Mathematics, you do not need 1,000 API calls. Fetch each unique subject once and map the result.
- Forgetting that `response.json()` raises a `json.JSONDecodeError` if the response is not valid JSON — an API that returns an HTML error page instead of JSON will cause this.
- Creating a new `requests.get()` call in every loop iteration when the headers are the same — use a `Session` object instead to set headers once and reuse the connection.
